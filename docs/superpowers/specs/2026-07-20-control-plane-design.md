# 后端控制平面设计

## 目标

在持续合并 upstream 的新版无限画布前端时，恢复 v0.3.0 的完整服务端能力：用户与管理员权限、模型渠道与 API Key 托管、模型代理、积分、提示词、公共素材、参考媒体和系统设置。

## 已知边界

- v0.3.0 的 Go 服务是独立 HTTP API，使用 Gin、GORM 和 SQLite/MySQL/PostgreSQL；它包含 `users`、`credit_logs`、`prompts`、`assets`、`settings` 五类持久化数据。
- v0.4.0 删除了 Go 服务、Next.js 的 API 反向代理和 `/admin` 页面。当前前端已是 Vite 应用，并强制使用浏览器本地渠道配置。
- 画布、个人素材和生成记录在 v0.3.0 与当前版本均主要保存在浏览器 IndexedDB/WebDAV；它们不属于旧 Go 后端的数据模型。本项目不会在恢复旧后端时伪造“已有云端画布同步”。

## 架构

```text
upstream/main
      |
      v
新版 Vite 画布  <---- 阶段 3：服务端模式适配 ---->  Go 控制平面
      |                                               |
      |                                               +-- 用户、权限、积分
      |                                               +-- 模型渠道与 API 代理
      |                                               +-- 系统设置、提示词、公共素材
      |                                               +-- 参考媒体、定时提示词同步
      |
      +---- IndexedDB/WebDAV（现有个人画布同步）

独立管理台  <-------------------------------------->  Go 控制平面
```

Go 控制平面放在仓库的 `server/` 中，保留 v0.3.0 的资源模型和 API 语义，但作为独立进程监听自己的端口。管理台作为独立应用维护，不重新塞入 upstream 的 `web/` 目录。新版画布仅通过一层明确的服务端模式客户端调用控制平面；本地直连模式继续保留。

## 分阶段交付

### 阶段 1：恢复独立 Go 服务

从 `v0.3.0` 迁入 Go 代码到 `server/`，调整 Go module 与导入路径，保留原有 `/api`、`/api/v1`、`/api/admin` 路由、数据库模型、认证、积分、模型代理、提示词同步和参考媒体能力。使用环境变量配置数据库、JWT、初始管理员和前端允许来源。提供独立 Docker 服务和 Go 测试命令。

完成条件：服务可独立启动；健康检查、认证、管理员设置、模型代理的无凭据拒绝路径和 SQLite 自动迁移均有自动化验证。此阶段不修改新版画布调用方式。

### 阶段 2：恢复独立管理台

从 v0.3.0 的管理页面迁出用户、积分、设置、提示词和公共素材界面，作为独立 `admin/` 应用。它只调用 Go API，不依赖新版画布的页面、路由或状态管理。

完成条件：管理员可在独立地址管理旧后端已有的全部资源，模型供应商 Key 只存在于服务器私有设置中。

### 阶段 3：为最新版画布增加服务端模式

在 `web/src/services/api/` 和 `web/src/stores/` 增加可切换的服务端模式：会话、公开模型清单和生成请求走控制平面；本地模式仍保留当前浏览器直连行为。只由服务端模式持有模型渠道，浏览器不得得到上游供应商 Key。

完成条件：同一新版画布可在本地模式与登录后的服务端模式之间选择；服务端模式完成图片、聊天、音频和视频请求的鉴权、代理和积分记录。

### 阶段 4：按需增加画布云同步

这是独立功能，不作为恢复 v0.3.0 后端的前置条件。若需要多人画布或跨设备的账号级同步，另行设计项目、媒体对象、版本冲突和权限模型；在此之前继续使用现有 WebDAV 同步。

## 数据与部署

- 保留 v0.3.0 的数据库表和字段。已有旧实例先做数据库备份，再对新服务做只读验证后切换。
- 开发环境可用 SQLite；多人/生产环境使用 PostgreSQL 或 MySQL，并将参考媒体放入可备份的持久卷或对象存储。
- 对外部署使用 HTTPS；控制平面 CORS 仅允许画布和管理台的明确来源。
- 默认管理员、JWT 密钥、OAuth 密钥和模型渠道 Key 全部只通过环境变量或后端私有设置进入服务端，禁止写入 `web/` 的运行时配置或浏览器存储。

## 上游更新规则

- `upstream/main` 只作为上游事实来源，不向其推送。
- `integration/backend-control-plane` 承载 `server/`、`admin/` 和新版前端的最小适配层。
- 每次同步先在单独分支合并 upstream，再运行服务端测试和前端类型检查；冲突仅在适配层解决，不回写上游画布实现。
- 新版前端的直接调用接口不被改造成旧管理台依赖，所有后端专用逻辑留在明确的服务端模式模块中。
