# 待测试

- Tripo DCC Bridge 安装教程：核对官方 ZIP、Blender 4.1+ 安装启用流程及插件实际监听端口；通过本地 HTTP 画布，经用户确认用已有 GLB/FBX 验证导入，分别报告 MCP 只读场景查询与 Bridge 文件导入结果，不把 Studio 订阅要求推断为第三方许可结论。本次未执行安装或导入。

- Blender MCP 安装说明：按 `docs/setup-blender-mcp.md` 检查上游自动 setup 与分步安装路径，确认 AI 终端不支持交互时不会假装安装成功；保留已有 MCP 配置，关闭遥测后通过当前客户端读取真实场景，不修改场景。单独安装 MCP 不应被描述成已配置 60600 导入桥接。本次仅核对上游说明，未在本机执行安装。

- AI 启动说明与 `setup-canvas` Skill：将 `docs/setup-canvas.md` 发送给有本机 shell 的 AI，应启动或复用前端、代理和 Canvas Agent，在不暴露 token 的情况下打开连接页面，并通过 MCP 或鉴权 HTTP 读到真实画布状态。检查缺依赖、端口占用、未加载 MCP、只有远程 shell 和纯聊天环境；不得杀掉已有进程，也不得把配置写入成功当作连接成功。本次仅新增说明，尚未运行启动验收。

- `scene-build` Skill：提供一张场景参考图后，应自动分析并生成可编辑的对象清单，无需用户手写 JSON；建筑、道具、植物等对象生成独立单体图并按对应图片生成 3D，角色应先生成一致的前/左/后/右多视图再生成 3D；生成状态确认成功后调用 `canvas_import_to_blender`，等待导入完成，再通过 Blender MCP 按参考图摆放模型、设置相机和灯光、保存 `.blend`，并如实区分已启动、已完成和失败。不得误删用户已有 Blender 场景，也不得超出用户范围继续渲染。

- 本地一键启动：在仓库根目录执行 `node scripts/dev.mjs`（或 `npm run dev`），应同时启动 Vite `:3000` 和 canvas-proxy `:23210`，日志带 `[web]` / `[proxy]` 前缀。「配置 → 本地代理」应默认开启（显示为内置转发代理，开关锁定），Tripo 生成无需再单独跑 npx。`:23210` 已有服务时应复用；`:3000` 被占用时应拒绝启动。加 `--agent` 应一并启动 Canvas Agent。Ctrl+C 或任一进程退出时应全部停止，两个端口都释放。
- 首页 Tripo 联名：标题应为「无限画布 × [Tripo 图标]」，副标题为「Agent 驱动的 3D 创作工作流」；黄色图形保持原色，黑色折线和 TRIPO 字样跟随主题，深色模式仍可读。两个主按钮下方应有「获取 Tripo API Key」：国内版链到 `https://developers.tripo3d.com/zh`，海外版链到 `https://developers.tripo3d.ai/zh`。README 的 3D 与 Tripo 配置段应列出同样两个购买入口。
- Tripo 3D 生成：配置弹窗新增渠道时，apiFormat 应可选「Tripo」，选中后 Base URL 自动填 `https://openapi.tripo3d.com`；模型能力列表应出现「3D」，模型选择应直接列出 `v3.1-20260211`、`v3.0-20250812`、`v2.5-20250123`、`P1-20260311`、`P2-20260801`（Tripo 无模型列表接口，不应发起 `/v1/models` 请求）。保存渠道并刷新页面后，该渠道的 apiFormat 应仍是 Tripo，不得变成 OpenAI。偏好设置应出现「默认 3D 模型」。
- Tripo 3D 生成流程：Tripo 的 `/v3` 接口不返回 CORS 头，必须先开启「本地代理」；未开启时生成应报出可读错误而不是静默失败。生成配置节点的模式选择应出现「3D」，文本节点提示词面板与 3D 节点提示词面板都应显示 3D 模型选择和 3D 设置。仅有提示词时应走文生 3D；上游连接图片节点时应先上传图片再走图生 3D。生成中节点显示进度占位，成功后应显示可用鼠标拖拽旋转、滚轮缩放的 3D 模型（three.js 从 CDN 按需加载，需要联网）；预览图先于模型显示为占位。实测文生 3D 约 3 分钟、消耗 10–30 credits，图生 3D 约 80 秒、20 credits。
- Tripo 3D 设置：3D 设置面板应包含贴图开关、PBR 材质、贴图质量（标准/精细/极致）和面数上限；面数上限留空表示自动，填写超出该模型允许范围的值时应显示 Tripo 返回的原文提示（不同模型范围不同，例如 P2 为 48–50000），而不是被前端拦下。设置改动应记录在节点上，重新生成沿用该节点设置。
- Tripo 3D 持久化与恢复：生成中刷新页面，节点应凭保存的任务 ID 继续查询而不是变成错误态；任务终态失败才清除任务 ID，超时或网络失败应保留可重试。生成成功后关闭画布再打开，3D 节点应从本地存储读出模型和预览图正常显示（Tripo 签名 URL 24 小时过期，不应依赖远端地址）；此时即使关闭本地代理也应能正常显示。3D 节点右键应可下载 `.glb`。画布放 3 个以上 3D 节点并反复删除重建，不应出现白屏或 WebGL 上下文耗尽。
- Tripo 图片生成：Tripo 渠道的模型列表应同时列出图片模型 `seedream_v5`、`seedream_v4`、`banana`、`banana_pro`、`banana2`、`chat_image_2`、`chat_image_2.5_flare`、`chat_image_2.5_sunburst`、`chat_image_1.5`、`chat_image_1`，且能力应识别为「图片」而不是「3D」。仅有提示词时走文生图；连接参考图节点时应先逐张上传再走图生图。Tripo 没有 `n` 参数，要多张图就会发多个任务、分别计费。产物应从 CDN 取回并像其他图片生成一样存到本地；图片产物走的是不发 CORS 头的 CloudFront 域（与 3D 产物 CDN 不同），这一步下载同样经本地代理，不应在控制台报 fetch 失败。图片生成和 3D 走同一套 `/v3` 接口，同样需要本地代理；未开启代理时两者都应立即提示去开启，而不是只在控制台刷一堆 CORS 错误。
- Tripo 生图模板：当前模型属于 Tripo 渠道时，图像设置应出现「模板」选项（无 / T-pose / 角色补全 / 3D 增强 / 设计变体 / 全身人物），其它渠道不显示。选中模板后提示词应变为可选：画布、配置节点和工作台都能在空提示词时直接生成，请求体应带 `template` 且空提示词时不发 `prompt`；提示词仍可叠加发送。切回「无」后空提示词应再次被拦住。重试应沿用节点上保存的模板。
- Tripo 多图图生图：连接两张及以上参考图时，请求体应只有 `inputs` 数组、不要带 `input`；只连一张时仍只传 `input` 字符串。`input` 不能传数组（传了会被忽略，任务仍会按无参考图跑下去并扣 credits）。
- Tripo 图片尺寸按模型适配：各系列接受的尺寸参数不同，请求应自动适配而不是报错。`seedream_v4` 只接受 2K 和 4K，`seedream_v5` 只接受 2K 和 3K，因此画布选 1K 或 4K 时应就近贴到该模型允许的档位，而不是返回 1004。`banana` 和 `banana_pro` 只接受固定像素表（`1024x1024`、`832x1248` 等），其他情况退回 `aspect_ratio`。`banana2` 用 K 档位加 `aspect_ratio`。`chat_image` 系列只接受具体 WxH 或字面量 `auto`，不接受 K 档位；只有 `chat_image_2`、`chat_image_2.5_flare`、`chat_image_2.5_sunburst` 接受 `quality`（发给其他模型会直接 1004），`background` 只对两个 2.5 模型生效。
- Tripo 双区域：默认应内置两个渠道，分别对应国内版（`https://openapi.tripo3d.com`）和海外版（`https://openapi.tripo3d.ai`），各自预置 `v3.1-20260211` 和 `seedream_v5`。apiFormat 选为 Tripo 时，渠道编辑器应出现区域切换并同步改写 Base URL，其他格式下不显示。两个区域是独立账号，各渠道保存各自的 API Key，一个区域的 Key 不应能通过另一个区域的鉴权；两个区域都需要本地代理。
- 3D 节点双击放大：双击已有模型的 3D 节点应弹出大窗口（宽 80vw、高 72vh），标题为节点名，窗口内无需先切交互模式就能拖拽旋转、滚轮缩放；节点处于移动模式或交互模式下双击都应生效。空的 3D 节点双击不应弹窗；图片节点双击仍看大图、文本节点双击仍进入编辑、空白处双击仍弹新建菜单。关窗后再反复开关多个 3D 节点的窗口，不应出现白屏或 WebGL 上下文耗尽（弹窗已设 destroyOnHidden，关闭时会释放上下文）。大窗口右下角应有相机图标「导出当前视角为图片」：先旋转/平移/缩放到想要的角度再点，应在源 3D 节点右侧生成一张当前画面的图片节点并连线，大窗口关闭，图片被选中。导出应带上当前查看模式（实体 / 固有色 / 白模 / 线框 / 骨骼）和动画定格；透明处应填查看器背景色，不要出现黑底。未点加载模型、只显示截图的节点双击放大后再导出，也应是当前窗口里调过的角度，而不是节点上那张默认截图。导出失败应提示「无法导出当前视角」。
- 3D 查看器查看模式：大窗口左上角应有实体 / 白模 / 白模+线框 / 线框 / 骨骼五个模式（画布上的 3D 节点不显示这些按钮，节点上只保留原来的实体显示）。白模应是无贴图的中性灰，只看形体；白模+线框应能看清布线且线不会和面闪烁打架；线框模式底色偏暗、线为青色；骨骼模式下网格半透明、骨架画在网格之上（透视可见）。切模式不应重新加载模型，也不应丢失相机角度。没有骨骼的模型不应出现「骨骼」按钮。逐个模式来回切换多次后，切回实体应完整恢复原始贴图材质。
- 3D 节点默认显示截图：画布上放多个 3D 节点时，节点应默认显示一张模型截图（右下角有「点击加载模型」提示），点一下才加载真实模型。重点验性能：放二十几个 3D 节点，画布拖动和缩放应明显比以前流畅，浏览器控制台不应出现 WebGL 上下文被回收的警告。同时最多 4 个节点是真实渲染的，点开第 5 个时最早点开的那个应自动退回截图——注意这是设计如此，不是丢状态。已经点开的节点在你正拖动模型时不应被退回截图。
- 场景拆件：图片节点的「拆件」应先弹窗、自动识别画面里的物件并列出清单，此时还没有花生图 credits。要验清单本身：改一项的名字、删一项、手动加一项、点「重新识别」，这四项都应生效，改完的名字应成为生成出来的节点标题；模型返回的格式不稳定（带 ```json 围栏、前后夹着解释文字、或者干脆是 markdown 列表）都应能解析出清单，实在解析不出时应显示「没有识别到可单独取出的物件」并且还能手动添加；识别超过 12 个时应只保留前 12 个并显示截取提示，「添加一项」在满 12 项后应禁用。
- 场景拆件生成：确认后应逐个生成、一次只发一个请求（不要并发），每个组件在画布上是独立图片节点，按每行 3 个排在原图右侧，从原图连线；两个以上组件应自动打成一个「场景组件」组并一起选中，只剩一个成功时不打组。要验失败处理：中途某个组件失败应提示「有 N 个组件生成失败」并保留其余组件，全部失败才报错且原节点回到正常状态；撞到并发上限应提示等待秒数并自动重试一次；点停止应中断整个拆件而不是只跳过当前组件。
- 场景拆件的透明背景：用支持透明背景的模型（OpenAI 兼容渠道，或 Tripo 的 chat_image_2.5_flare / sunburst）拆出的组件应是透明底，放到深色背景上边缘不应有白框；用不支持的模型（Gemini，或其他 Tripo 图片模型）时弹窗顶部应提前显示「不支持透明背景」的提示，产出为不透明底，但流程本身应照常跑完。
- 场景拆件的后续操作：拆出的组件节点应和普通图片节点一样可用——局部编辑、裁剪、多角度、重试、存资产、下载都应正常，把其中一个单独连到 3D 节点应能生成模型。生成记录里应能看到这次拆件（记在原图节点上，操作标记为 decompose）。另外注意「拆件」和原有「切图」是两回事：切图仍应是按行列切像素，两个工具都应出现在图片节点工具栏里（拆件默认显示，升级后原有的快捷工具设置会重置一次）。
- 3D 节点自动截图：没有预览图的 3D 节点（最容易复现的是本地拆件产出的部件节点，Tripo 生成的节点自带预览图）第一次应短暂加载一次模型、自动截一张图存下来，之后就一直显示这张图。要验：一次性拆出十几个部件时，它们应依次完成截图而不是全部卡在占位状态（同一时刻只有 4 个在渲染），全部完成后画布应回到零个活动上下文；刷新页面后这些截图应还在（存在本地存储，不依赖远端地址）；删除节点后其截图应随存储回收一起清掉。
- 3D 查看器按需渲染：静止的模型不应持续重绘。要验切换查看模式（实体 / 固有色 / 白模 / 线框 / 骨骼）后画面应立刻更新，缩放大窗口后模型应跟着重新取景，点「相机复位」应立刻回到初始机位——这几项都依赖按需渲染的重绘触发，漏掉任何一个都会表现为「点了没反应」。带动画的模型播放时应流畅不掉帧，暂停后应停住且不再持续渲染。
- 3D 查看器固有色模式：大窗口左上角应在「实体」旁多一个「固有色」，切过去应看到模型只显示基础色贴图——没有明暗、没有高光和阴影，颜色均匀平铺，和「实体」的区别就是完全不受光照影响（这正是检查二次元平涂贴图的用法）。要验几种材质：带贴图的普通产物应显示贴图原色；开了 PBR 的产物在这个模式下应看不出金属和粗糙效果；没有贴图只有纯色材质的产物应显示那个纯色而不是变黑；贴图带透明通道的部分（头发、睫毛等）应保持镂空而不是糊成不透明。多材质的 FBX 产物（材质被拆成多组）每一组都应正确显示，不应只有第一组有贴图。切到固有色再切回实体，贴图和材质应完整恢复；带骨骼的模型在这个模式下播放动画应正常跟着动。
- FBX 加载：H 系列（v3.x）开四边面生成的产物、以及自动绑骨/套用动画选 fbx 输出的产物都是 FBX，应能像 glb 一样在画布节点和大窗口里正常显示、旋转，而不是一直转圈或报加载失败（之前只有 GLTFLoader，FBX 直接加载不了）。格式是按文件头的魔数判定的（glb 开头是 `glTF`，FBX 是 `Kaydara FBX`），不依赖 URL 后缀，因为本地存的是 blob 地址。带骨骼的 FBX 应同样能看骨架和播放动画。切到格式转换产出的 OBJ / STL / USDZ / 3MF 仍然只能下载，不做预览。
- 内置四视图：图片节点悬停工具栏应有「四视图」按钮（和调 Tripo 的「多视图」并列，两个都默认显示）。点它应发四次改图请求（走当前配置的图片模型和渠道，不是 3D 模型），产出正/左/后/右四张图，按 2×2 摆在源节点右侧并连线，节点标题是视图名。四次是并行的，所以要验：某一个视角失败时应提示「有 N 个视角生成失败」并保留其余成功的视角，而不是整批丢掉；四个全失败才报错。产出的节点带视图归属，应能直接连去 3D 节点走多视图生 3D。注意内置四视图不带 Tripo 任务 ID，所以这些节点不应出现「多视图」的编辑弹窗（那个只对 Tripo 产出的四视图有效），点「多视图」应是重新生成。视角之间的一致性靠图片模型自己保证，实际效果需要真实模型验。
- 多视图上传空文件修复：图片节点点「多视图」（调 Tripo 的那个，不是内置四视图）应能正常跑完，不再报 `code: 2003`「The image file is empty」——之前把节点里的 blob 地址当 dataURL 去转文件，上传的是 0 字节文件。要验的是这条路径本身：单图点「多视图」应出四张图；刚生成完就点、以及刷新页面后再点（这两种情况节点的 blob 地址来源不同）都要试一次。已有四视图上点「多视图」走的是编辑改图、不重新上传，应不受影响；内置四视图、图生 3D、多视图生 3D、多参考图改图这些同样要上传图片的路径也应照常工作（它们本来就先读成 dataURL）。
- 四视图并发与限流：四个视角是**串行**发的，不是并行——生图并发通常只有 1，并行会直接撞上「You have exceeded the limit of generation」（Tripo `code: 2000`）。所以要验：点一次四视图应看到四张图依次出现，而不是一起失败。真撞到限流时应提示「触发生成并发上限，N 秒后重试这个视角」并在等待后重试该视角一次；N 取接口返回的 `Retry-After` 头，没有该头时用 4 秒，并被夹在 2–30 秒之间（防止接口给出离谱的值把整轮拖死）。重试仍失败只算这一个视角失败，其余视角保留。等待期间点取消应立即停止，不该等完退避才响应。注意 401、内容审核（1004）这类非限流错误不应触发重试，应直接算该视角失败。
- 模型拆件：3D 节点的「3D 操作」→「分割部件」现在多一个「拆成独立部件节点」开关（默认开）。开着跑分割后，除了原来的整体分割节点，还应在它右侧竖排出现每个部件一个 3D 节点（人物模型大致是脸、头发、身体、手臂等），标题是部件名，都从分割节点连线，每个都能单独预览、下载、继续做 3D 操作。部件是在浏览器里从分割产出的 glb 拆的（Tripo 只返回一个整体 glb，不返回分开的文件），所以要验：部件位置应保持在整体里的相对位置，不应全都堆到原点；同一部件的多个网格（如 hair_1、hair_2、Hair.003）应合并成一个节点，不该拆成三个。v1.0 分割模型不做语义标注、网格可能没有部件名，此时应提示「没有可识别的部件名」并只保留整体节点，不能报错或产出一个和整体重复的节点——建议用 v2.0-20260430 测。关掉开关时行为应和以前完全一致。部件节点没有自己的 Tripo 任务 ID，对它再做 3D 操作应走上传文件而不是任务链。
- 四边面线框：用四边面（quad）生成的模型切到线框或白模+线框时，应看到四边面的布线，而不是每个四边面里都多一条对角线。这一条是**首轮验收时实测不生效的**（显示的仍是三角面），原因是共用边原来按顶点下标判断，而导出器会在 UV 和法线接缝处把同一位置的顶点拆开，两个三角形持有不同下标、一条共用边都匹配不上；现在先按坐标（保留 5 位小数）合并顶点再做拓扑判断。修复后用真实产物再验一次：切线框应看到四边面回路。判定方式是丢掉「被两个三角形共用、且在两者中都是最长边」的边——8×8 正方形网格实测，顶点合并前后（模拟导出器拆点）都正好还原 64 条对角线，25000 面（面数上限）规模下合并耗时约 30 毫秒，切模式不应有可感知的卡顿。两个已知边界情况需要留意：接近正三角形的三角面模型会因为「最长边」并列而误判，此时会自动放弃还原、退回普通三角线框（正八面体实测 100% 误判，已加保护），所以三角面模型的线框显示应完全不受影响；带骨骼的模型也会退回三角线框，因为四边面线框是独立的线段几何、无法跟着骨骼变形（宁可显示三角边，也不要一个卡在绑定姿态的线框）。
- 3D 查看器骨骼与动画：绑骨后的模型（自动绑骨产物，或套用动画产物）在大窗口里应显示骨架、左下角显示骨骼根数；带自带动画的模型应在右下角出现播放 / 暂停按钮，多段动画时还有下拉框可切换片段，左下角显示片段数量。播放中切到线框或白模+线框时，线框应跟着骨骼一起动，而不是停在绑定姿态。暂停后切模式、切片段都不应让动画自己恢复播放。相机复位按钮应回到打开时的取景。没有骨骼也没有动画的静态模型，左下角应显示「静态模型」，且不出现播放按钮。
- Tripo 鉴权报错可读：填错 API Key，或把国内版的 Key 填到海外版渠道（两个区域是独立账号，已实测：同一个 Key 在 `.com` 正常、在 `.ai` 返回「Invalid API key」），生图、生 3D、上传参考图、各项 3D 操作都应提示鉴权失败并说明区域不通用，而不是只报「Request failed with status code 401」让人去翻网络面板。代理开关开着但没启动命令时，应提示连不上本地代理。任务本身失败（内容审核、超时）的提示应不受影响，取消生成仍显示已取消。
- Tripo 3D 拓扑：3D 设置面板在选中 P2、v3.0 或 v3.1 时应多出一行「拓扑」（三角面 / 四边面），选 P1 或 v2.5 时这一行应隐藏——P1 会直接报 1004（已实测：「quad is only supported by model P2-20260801」），所以不支持的模型不发这个字段。选四边面时下方应出现提醒：H 系列（v3.x）开启后产物是 FBX，画布内无法预览只能下载（这点需真实生成验证）；P2 开启后面数上限降为 48–25000，超出时应原样显示 Tripo 的报错。该设置应跟着节点保存，重新生成时沿用。另外要验记录到节点上的值：全局设置留着「四边面」但用 P1 或 v2.5 生成时，节点上应记成三角面（请求本来就不发这个字段），否则查看器会拿一个三角面产物按四边面去还原布线。
- Tripo 图生 3D 鉴权：已在渠道里配好 Tripo API Key（生图能成功）时，图生 3D、多视图生 3D、图生多视图都不应再报「请先配置 API Key」——之前上传参考图这一步没有解析模型所属渠道，读的是空的顶层 apiKey。多渠道并存（例如第一个渠道是 OpenAI、Tripo 在后面）时尤其要验。
- Tripo 3D 提示词可选：3D 节点连上图片后，提示词输入框为空也应能点生成（图生 3D / 多视图生 3D 本身不需要提示词，Tripo 也不接收），占位文案应提示“可直接生成、提示词选填”。没有连图时仍要求提示词（文生 3D），按钮保持置灰；文本、图片、视频、音频四个模式不受影响，空提示词仍不可生成。另外 3D 提示词输入框之前缺少占位文案、会直接显示翻译 key，现在应显示正常文案。
- 3D 连图后隐藏提示词框：3D 节点连上图片后，提示词输入框应整块消失，位置换成一行说明——连 1 张说走图生 3D，连 2–4 张说走多视图（并说明单张图接到左侧对应视角接点、打组的图在组内标记正/左/后/右，未指定的按连线顺序补上剩下的视图），连超过 4 张说只用前 4 张；三种说明都要写明无需提示词。同时放大编辑按钮和提示词库入口应一并隐藏（没有输入框，放大也没意义），模型选择和 3D 设置仍在，生成按钮保持可点。断开所有图片后输入框应原样回来，之前输入过的提示词不应丢失。放大编辑窗开着时连上图片，窗口应自动关闭而不是留一个会被丢弃的输入框。文本、图片、视频、音频四个模式的输入框不受影响。
- 无提示词任务的重试：让一个不需要提示词的生成失败（最容易复现的是图生 3D 或多视图生 3D：连上图片、提示词留空、断网或填错 Key 让它失败），然后点节点上的重试——应真的重新发起请求，而不是弹「找不到提示词，无法重试」。多参考图改图（图片节点连图片、提示词留空）同样应可重试。反过来要确认没放宽过头：文本节点和音频节点在提示词为空时点重试仍应提示缺提示词（这两种接口本身就必须有提示词），图片和 3D 在既没有提示词也没有连参考图时也仍应提示。
- 3D 节点重试的走向：3D 节点生成失败后点重试，应重新跑 3D 生成并把模型写回这个节点本身，不应新建节点、更不应变成生图（之前重试对 3D 节点没有分支，会一路落到图片请求上，把图片结果写进 3D 节点的 content）。文生 3D 和图生 3D 两种失败都要验。另外视频节点的「获取任务状态」按钮和重试共用一个回调，改动后要顺带确认它仍然只查询任务状态、不会触发重新生成。
- Tripo 多视图生成 3D：给 3D 生成连 2–4 个图片节点时应走多视图生成，而不是只用第一张。正面视图必填。单张图接到 3D 节点左侧四个接点（正/左/后/右）中的一个即占用该视角；打组后在组内成员角标上标记视角。接点或角标指定的视角优先占位，其余未指定的按连线顺序补上还没被占用的视角（都没有指定时，第一张就是正面）。连超过 4 张时应明确提示只用了前 4 张，不能静默丢弃。只连 1 张时仍走图生 3D，只有提示词时走文生 3D。
- 多视图视角不重复：视角是对整组图片统一分配的，任何一组连线都不应出现两个相同视角。重点验这几种撞车情形：①把一张四视图里的「左侧」图和一张普通图连给 3D 节点 —— 应得到左侧 + 正面，而不是两个左侧（旧版逐张按下标算，第二张也会被判成左侧，于是既重复又缺正面，接口直接报 front view is required）；②把两组四视图里的两张「正面」连上 —— 应得到正面 + 左侧，而不是两个正面（这种服务端不报错，会直接产出一个诡异模型，是最难发现的一种）；③一张「右侧」图加 3 张普通图 —— 应得到右侧 + 正面 + 左侧 + 背面，四个视角齐全不重复。另外要确认没有破坏正常情况：整组四视图连上时四个视角应各就各位（打乱连线顺序也应按各自自带视角走），全是未指定视角的普通图时仍按连线顺序取正/左/后/右。把两张散图分别接到正面和左侧接点，即使连线顺序相反，发出的请求也应是正面+左侧。只连「背面 + 右侧」这类拿不出正面视角的组合，应由接口报出正面视图必填，而不是前端悄悄改一个视角凑数。
- 多视图自动打组：内置「四视图」和 Tripo「多视图」跑完后，四张图应被一个组节点包住（标题「四视图」，组上显示成员数），四张图仍各自从源节点连线。要验：拖组应带着四张图一起走，不是只动框；把组连到 3D 节点应等于把四个视角一起送进去（不用再一张张连），且视角归属仍按各图自带的来，不受组内顺序影响；组和四张图都连到同一个 3D 节点时不应重复计成八张。组是虚线框、画在图片下层，不应盖住图片或挡住点击。右键组应能解散（解散后四张图和连线都保留），删除组应按现有行为处理成员。只成功一个视角时不应产生组（和手动打组的两个成员下限一致）。编辑多视图重跑一次，应得到新的一组四图和新的组，而不是塞进旧组。
- 生成历史：左侧面板「历史」页签应按时间倒序列出本画布的每次生成。逐项跑一遍：生图（含多张批量，应只出一条记录）、生视频、生音频、文生 3D、图生 3D、多视图生 3D、图生四视图、编辑多视图、3D 操作（贴图 / 绑骨 / 套动画 / 减面 / 分割 / 补全 / 格式转换）、局部编辑、多角度、失败后重试。每条应显示类型图标、状态点（进行中 / 成功 / 失败）、时间、模型；凡是走 Tripo 的那几项应带任务 ID，生图 / 生音频这类同步接口没有任务 ID，复制按钮应是置灰的。文本生成不入历史。
- 生成历史中断与恢复：视频或 3D 生成中刷新页面，历史里那条应先保持「进行中」并已带任务 ID；等续跑完成后应变成成功（不应新增重复记录），续跑失败则变成失败并带错误信息。中途点「停止生成」的那条应收束为失败并标「请求已取消」，不能永远停在「进行中」。
- 生成历史的搜索、筛选与清理：按提示词、模型名、任务 ID 搜索应能命中；类型下拉逐项筛选应只留对应类型；点定位图标应居中到对应节点，节点已删除时该按钮应置灰并提示「对应节点已删除」；单条删除和「清空」应只影响当前画布，刷新后仍生效（记录存在 localforage，不是内存）；删除整个画布后，该画布的记录应一并消失，其他画布的不受影响。
- 生成历史只存元数据（已知限制）：删除生成出来的节点、不存为资产，过一轮存储回收后结果文件会被清掉，历史记录仍在但只能用来回查任务 ID / 提示词和重新生成，不能把文件找回来；面板底部应一直有这行说明。历史目前不参与 WebDAV 同步，只存本机。
- 参数行（ComfyUI 式）：选中节点后，下方面板底部应有「参数」开关，展开后直接列出该模式的全部参数行。五种模式逐个验：生图（质量 / 尺寸 / 张数 / 透明背景）、视频（时长 / 分辨率 / 比例 / 音轨 / 水印 / 模式）、音频（音色 / 格式 / 语速 / 指令）、3D（贴图 / PBR / 贴图质量 / 拓扑 / 面数上限）、文本（推理强度 / 生成条数）。改任一项后应立刻写进节点、刷新后仍在，且发出的请求用的是改后的值。折叠状态是本次会话的界面偏好，不写进画布文档（刷新后回到默认展开）。
- 参数行不应改变节点几何：展开 / 折叠参数区时节点本身的大小、位置、图片长宽比和缩放都不能变；面板仍是节点下方那块 600px 浮层。
- 配置节点作为参数节点：新建配置节点，从它右侧的输出圆点连到一个生成节点（这个输出端点以前是隐藏的）。连上后配置节点自己的「开始生成」按钮应消失，改显示「作为参数节点，供 N 个节点使用」，其下方面板从「组装提示词」切换为参数行。下游节点的参数行应变成只读并标出来源节点标题，带定位和断开两个按钮，点断开后应恢复可编辑。
- 参数节点的覆盖优先级：全局配置 < 节点自身参数 < 参数节点。在参数节点上改贴图质量，下游 3D 节点即使自己存过别的值，实际请求也应发参数节点的值；断开连线后应回到节点自身的值。一个参数节点连多个下游节点时，应同时对所有下游生效（计数要对）。重试和 3D 后处理操作（贴图 / 绑骨 / 减面等）也应继承参数节点。
- 参数节点不应被当成素材：连上参数节点后，下游节点的引用条里不应出现这个配置节点的缩略图，引用数量也不受影响。未连出的配置节点仍应是原来的扇入枢纽（多个素材连进它，它再连到生成节点），行为不变。
- 老画布的配置节点不应被误判成参数节点：配置节点每次生成都会自动连一根线到生成结果上，这类线不带参数标记，所以已有画布里的配置节点应照旧显示「开始生成」和「组装提示词」面板。用旧画布验一遍：打开一个配置节点跑过生成的画布，节点行为应与升级前完全一致；只有从配置节点右侧圆点手动拉出的连线才把它变成参数节点。另外，参数连线不应被当成生成输入，也不应影响失败重试时找回原来的配置节点（重试应仍带上原来的提示词和参考图）。
- 3D 视角接点：3D 节点左侧应竖排四个接点，自上而下标正面 / 左侧 / 背面 / 右侧。把一张散图的右侧圆点拖到其中一个接点，连线应落到该接点而不是节点中线；该图即占用对应视角。把第二张图接到同一个接点时，两张图应互换视角，而不是两个都变成同一个（一个接点一张图）。从接点反方向拉到图片，效果应相同。只连 1 张仍走图生 3D。
- 组内标记视角：多张图打组后整组连到 3D 节点（一根线、不走四个接点）。组内每张图左上角应有视角角标，未指定时显示「未指定」，点击在正/左/后/右之间循环；循环到已被组内另一张占用的视角时应互换。角标指定的视角应就是发给多视图接口的视角，刷新后仍在。组和散图混连时，接点上的散图与组内角标互不抢同一个视角，未指定的再按连线顺序补。
- 连线标签：散图接到接点后，连线中点仍可显示该视角标签（与接点文案一致）；组的那一根线上用「·」连接显示组内各图视角，点标签仍可逐张改。只连 1 张不应出现标签；超过 4 张只有实际用到的前 4 张有标签。
- 3D 查看器平移：节点内预览和双击的大窗口里，右键拖动（触控板双指拖动）应能把模型在画面里移动，左键拖动仍是旋转、滚轮仍是缩放；平移后模型跟手，视角转到侧面或背面后拖动方向也应与手势一致。查看器内右键不应弹出节点的右键菜单（画布空白处和其他节点上的右键菜单不受影响）。点「相机复位」应同时复位旋转和平移，回到沿 X 轴的默认机位。非交互状态的节点（未开启交互的 3D 节点）上拖动应仍然是拖动节点本身，不能被查看器吃掉。
- 面数上限滑块：3D 设置里「面数上限」应是 48–25000、步长 100 的滑块，默认 5000，右侧数字框可直接输入（超出范围应被夹到边界，输入非法值退回默认 5000）。「自动」开关打开时滑块应隐藏、生成时不发送 face_limit；关闭时用滑块的值。开关和滑块值都要能扛过刷新——重点验「自动」开着刷新后仍是开着（存的是 auto 标记而不是空值，空值会在每次加载时被默认值覆盖）。
- 面数上限的存量迁移（行为变化）：升级前留空（自动）的全局设置会被迁移成 5000，所以已有画布再生成 3D 时面数会被限制到 5000、结果与升级前不同；需要交给 Tripo 决定的用户要手动打开「自动」。另外节点自身存过的面数值、以及参数节点提供的面数值，都应照旧优先于全局设置。
- 多视图生 3D 的模型名：连 2–4 张图跑多视图生 3D 时不应再报 `invalid model 'DQdLKtaxCCl5eFsShrZSi::P2-20260801'`（1004）。模型选择器为了让两个渠道能提供同名模型，存的值是「渠道ID::模型名」，之前多视图这一条把复合值直接塞进了请求体。现在剥离统一放在 runModelOp 里，所以七个 3D 操作（重新贴图、绑骨、套动画、分割、补全、减面、多视图生 3D）都要顺带验一遍模型名能正常发出去；重点验多渠道并存、且两个渠道有同名 3D 模型的情况。
- Tripo 多视图图片：图片节点工具栏新增「多视图」工具（默认关闭——它和其他本地图片工具不同，会消耗 credits，可在工具栏「更多」里开启）。对普通图片执行会生成四视图，在右侧以 2×2 网格落成四个图片节点，各自连线并标注正面/左侧/背面/右侧。对这些生成出来的视图节点再执行该工具，应改为打开编辑弹窗，只填部分视图就只改这几个视图。编辑依赖原多视图任务，因此只对本画布多视图生成出来的节点可用。
- Tripo 3D 操作菜单：悬停已有模型的 3D 节点，应出现「3D 操作」菜单，包含重新贴图、自动绑骨、套用动画、减面、分割部件、网格补全、转换格式。每个操作打开同一个参数弹窗，字段按操作不同。除转换外的操作都应在源节点右侧新建 3D 节点并连线，并保存自己的任务 ID 以便继续串链。从已有模型的 3D 节点右侧圆点拉线到空白处，创建菜单顶部应同样列出这七项（空 3D 节点或从左侧圆点拉入时不应出现）；点选后关闭创建菜单并打开同一个参数弹窗。套用动画 / 网格补全在不满足串链条件时应置灰并显示原因，点了不应打开弹窗。点「3D 生成」等原有项仍应新建空节点。转换格式仍写回源节点、不新建节点。
- Tripo 操作串链限制：非本画布绑骨产生的节点上，「套用动画」应置灰并给出说明；非本画布分割产生的节点上，「网格补全」同样置灰——这两个接口 Tripo 只接受上游任务 ID，不接受上传文件。满足条件的节点上两者都应能跑通。其余操作对任意 3D 节点都应可用，包括重开项目后恢复的节点（任务 ID 丢失时会重新上传本地模型换取 token）。
- Tripo 自动绑骨前置检测：绑骨会先跑免费的可绑骨检测。对 Tripo 判定不可绑骨的模型，应直接中止并给出含识别类型的可读提示，且不消耗 credits。注意绑骨的模型枚举与生成模型不同，且只有部分骨架类型有预设动画，其余类型动画列表为空。
- Tripo 格式转换：转换写回**同一个节点**而不是新建节点（这些格式无法在 glb 查看器里预览），随后「3D 操作」菜单应出现「下载 FBX」这类对应格式的下载项。不提供 GLB，因为 Tripo 明确拒绝。转换完成后关闭再打开项目，下载应仍然可用——转换产物必须能扛过无用资源清理。转换过程中刷新页面应继续查询任务而不是丢掉，因为转换是计费任务。
- 同源转发代理（Docker 部署）：用当前源码 `docker compose -f docker-compose.local.yml up -d --build` 启动后，打开站点，配置弹窗的代理页签标题应为「转发代理」而不是「本地代理」，开关默认开且不可关，地址为 `/proxy` 且不可改，不应再显示 `npx @basketikun/canvas-proxy` 命令。点「测试连接」应成功（走同源 `/proxy/`）。填好 Tripo Key 后，不在本机跑 npx 也能生图 / 生 3D。自定义渠道若域名不在白名单（默认只有 OpenAI / Gemini / Tripo）应被拒绝转发并提示 host is not allowed；把该域名加进 `PROXY_ALLOW_HOSTS` 重建后应能通。访问 `http://站点/proxy/http://127.0.0.1/`、`http://站点/proxy/http://169.254.169.254/` 以及任意内网主机都应返回 403。短时间连续打 `/proxy/` 超过限流（8 次/秒、突发 20）应返回 503。`PROXY_URL` 设为空字符串重建后，页面应回到本机代理模式（开关可关、地址可改）。API Key 仍只存在浏览器本地，容器日志不应打印 Authorization 等请求头。
- 本地代理：配置弹窗应在「渠道」和「偏好设置」之间出现独立的「本地代理」页签，开关默认关闭。打开后应显示 `npx @basketikun/canvas-proxy@latest` 启动命令（端口非默认时自动追加 `--port`）、复制按钮，以及默认 `http://127.0.0.1:23210` 的地址输入框，失焦时自动补全协议并去掉末尾斜杠；「测试连接」应只在命令已启动时成功。开启代理后，拉取模型列表、生图、生视频、生成文本（含流式输出）、生成音频、自定义调用脚本、视频任务轮询、生成结果图片和视频的下载，以及 WebDAV 测试连接与同步都应经代理转发且功能正常，关闭后恢复直连。代理本身应原样转发请求方法、请求头、查询参数和请求体，SSE 响应按块透传不缓冲，`data:` 和 `blob:` 地址不受影响。
- 图像与视频尺寸设置：图像设置应将分辨率（`1k` / `2k` / `4k` / 自动）和宽高比（`1:1`、`2:3`、`3:2`、`4:3`、`3:4`、`16:9`、`9:16`、`21:9`、`9:21`、自动）拆成两项，并由二者计算 W/H。视频设置仍使用 `480p` / `720p` / `1080p`（以及自定义 p 值），比例为 `1:1`、`3:4`、`4:3`、`16:9`、`9:16`、`21:9`、自动，并由清晰度与比例计算 W/H。秒数应为 4–30 的滑杆，右侧显示当前秒数；比例为自动时应禁用 W/H。
- 视频内置请求：未配置调用脚本时，OpenAI 格式应按模板发送 `mode`、`first_frame`/`last_frame` 或 `image[]`、`generate_audio`、`watermark` 以及参考视频/音频，不再使用 `input_reference[]`；Gemini 格式应走 `predictLongRunning`，按模式发送 `image`/`lastFrame` 或 `referenceImages`，不再提示不支持视频。刷新后应能继续查询 Gemini 任务状态。
- 视频生成模式：视频设置应出现「首尾帧」和「全能参考」；1 张图按首帧、2 张图按首尾帧发送专门字段，超过 2 张即使选了首尾帧也按全能参考发送。内置请求和调用脚本的 `params.mode` 均为 `frames` 或 `reference`。
- Gemini 生图：Gemini 格式渠道和 Gemini 生图调用脚本应使用 `generationConfig.responseModalities: ["TEXT", "IMAGE"]`，比例和尺寸放在 `imageConfig.aspectRatio` / `imageConfig.imageSize`，不再发送 `responseFormat`。
- 视频调用脚本：能力为「视频」的模型打开「调用脚本」后应进入全屏分步配置；左侧按「看懂规则 → 让外部 AI 写 → 可用变量」展示，可用变量应包含 `videos`（参考视频 File 数组）和 `audios`（参考音频 File 数组）；「复制写脚本说明」应包含当前能力、可用变量、返回要求和写法约束。插入的模板应是带参数列表的 async function，并把 `params` 拆开；OpenAI 生图模板必须包含 `quality`、`size`、`count`、`background`。OpenAI 视频模板应使用 FormData，带上 `mode`、时长、尺寸、分辨率、配音、水印以及参考图/视频/音频；`mode=frames` 时应使用 `first_frame` / `last_frame`，`mode=reference` 时应使用 `image[]`，完成后轮询并下载 `/content`。把外部 AI 写好的脚本粘贴到右侧并保存后，画布连接参考视频或参考音频再生成时，脚本应能读取这些文件。
- URL 凭据导入：使用新的有效 `baseUrl` 和 `apiKey` 打开应用时，应新增独立渠道且不修改已有渠道；再次导入相同 Base URL（含末尾斜杠或 `/v1`）时只更新对应渠道并保持幂等；仅提供 API Key 或提供非法 Base URL 时，所有配置都应保持不变。
- 文档站导航与本页目录：手机宽度打开文档侧边栏时，顶部应显示当前文档分类及说明；展开后可在项目介绍、操作手册、开发文档、项目进度、商务合作和赞助支持之间切换，切换后分类标题及下方页面列表应同步更新；桌面端顶部分类栏保持不变，宽度达到 960px 时正文右侧应显示带层级折线的本页标题目录，点击可跳转，滚动时自动高亮当前标题；较窄宽度继续显示顶部折叠目录。
- Canvas Agent 生成流程引用：提示词仅包含已经通过 `referenceNodeIds` 传入的 `@[node:...]` 引用时，应直接把现有文本、图片、视频、音频或组节点连接到生成配置节点，不再创建重复的提示词文本节点；提示词包含普通文字时仍应创建独立的提示词文本节点。
- 视频画面截取：右键有内容的视频节点应显示「截取首帧」「截取尾帧」「截取当前帧」；三项操作应按视频原始比例在右侧生成并选中图片节点，同时建立视频到图片的连线；「截取当前帧」应使用播放器此刻停留的画面，截取过程不得改变原视频的播放位置。
- 文本节点：节点正文右上角不再显示「生图」按钮，文字内容应使用完整正文区域；节点上方工具条中的生图入口仍可正常创建生成配置。
- 多文本生成：生成次数大于 1 时只创建一个文本结果节点和一条来源连线；节点右上角显示实际生成成功的文本数量，点击后应像多图节点一样展开所有备选文本；点击「设为主文本」应立即替换正文，原主文本保留为备选，双击正文编辑后再次切换回来仍应保留修改。
- 组节点引用：组节点应使用透明、轻量的边框与标题样式，并显示右侧输出连接点；把组连接到生成节点后，组内有内容的图片、视频、音频、文本及可引用扩展节点都应作为输入，普通提示词面板的 `@` 列表应显示组内资源，生成配置的 `@` 列表应允许一次选择整组；组与单节点重复引用时不得重复发送同一资源。
- 多选打组：框选或点选至少两个节点后，应出现包住全部选中节点的圆角虚线框，框上方显示「打组」；点击后用组节点包住这些内容并保持原位置，随后选中该组。选中组后可通过顶部「解散组」、右键菜单或 `Ctrl/Cmd+Shift+G` 取消分组；已同属一组的节点再次多选时应显示「解散组」而不是再打一组。拖入组、组引用和左侧树形列表应继续可用。
- 节点参考栏：普通节点提示词面板、放大编辑器和生成配置输入框上方应显示当前输入节点；图片和视频显示缩略图并可悬停预览，文本、音频及扩展节点显示对应类型；组连接应展开显示组内每个有效内容节点，删除任一展开项都应断开整组连线。点击加号进入画布选择后可连续添加有效参考，已连接、目标自身、已通过组引用的组内节点及不可引用节点不可重复选择，按 ESC 或顶部提示返回输入框；新增连接后 `@` 列表应立即更新。
- 多图透明背景：展开包含透明 PNG 或 WebP 的多图节点时，主图与所有备选图的透明区域都应直接显示画布背景；切换主图前后不得出现白色或主题面板底色。
- 画布选择与平移：左下工具栏应能切换「选择」与「移动」模式并用图标显示当前模式；选择模式拖动空白区域应显示疏朗清晰的虚线框，虚线长度、间距和粗细在任意缩放比例下保持一致；移动模式应能从空白区域或节点上拖动画布。按住 Control 或空格应临时反转当前工具且不改变工具栏模式，即选择变移动、移动变范围选择；点击画布页任意按钮后按空格应只临时切换工具，不得再次触发该按钮；输入框和可编辑文本内仍可正常输入空格。中键平移以及 Shift/Cmd 追加选择节点应继续可用。
- 文档站国际化：访问文档站首页及 `/docs` 应直接显示英文，不得出现重定向循环；切换简体中文后 URL 应带 `/zh-CN` 且首页、顶部导航、侧边栏、正文、搜索框和页面操作文案均显示中文；刷新、站内跳转和再次切回 English 后语言应保持正确，搜索结果与 Markdown/LLM 文档内容不得混入另一种语言。
- 国际化基础框架：从页面右上角切换简体中文或 English 后，首页、顶部及移动端导航、版本弹窗、配置主面板、渠道编辑、模型选择、页面标题、页面描述和 Ant Design 内置文案应立即切换，刷新页面后保持所选语言；偏好设置中不应再显示语言选项，WebDAV 同步错误、提示词来源及其他尚未接入翻译的业务模块暂时仍可能显示中文。
- 全局弹层主题：全站 Dropdown、Menu、Select、Cascader、TreeSelect 等弹层在浅色主题下应使用白色背景、轻灰悬停和选中态，在深色主题下应使用深色背景与低对比度浅色交互态，不应再出现默认黑灰色块、文字对比不足或单个页面配色不一致。
- 画布节点缩放稳定性：选中任意节点并反复拖动四角缩放时，节点工具条应在缩放期间隐藏、松开后恢复，页面不应再出现 `Maximum update depth exceeded`。
- Agent MCP 初始化状态：首次进入空白对话、点击「新对话」或恢复历史对话后，无需先发送消息，对话区应立即显示 Codex 会话准备，并列出 `codex_apps`、`infinite-canvas`、`node_repl` 等完整 MCP 服务状态；全部服务进入终态前可输入并保留草稿，但发送按钮、上传和回车提交应禁用；可选 MCP 失败时应提示警告但允许发送，`infinite-canvas` 缺失或失败时应阻止发送并显示明确原因；首轮及后续任务运行期间再次收到的 MCP 状态只进入诊断日志，模型开始处理及回复完成后对话区不应残留初始化卡片。
- Agent 模型设置：连接 Canvas Agent 后，输入框左下方应显示当前 Codex 模型与推理强度；模型列表应来自当前账号实际可用模型且不显示内部审查模型或重复项，切换模型后强度选项随模型能力更新且无空白选项，刷新页面后保留选择，发送任务时实际使用所选模型和强度；本地控制台与右侧「日志」应记录本轮使用的模型和推理强度。
- Agent 新对话响应：一轮对话完成后点击「新对话」，聊天内容应在服务端确认切换后清空并进入空白对话；后台应串行创建线程并预热 MCP，多个标签页应按同一会话版本同步，旧 HTTP 响应不得覆盖较新的 SSE 状态，初始化完成前不能发送到上一条会话或重复创建线程；重启 Agent 后应重新恢复并预热已有活动线程，无法恢复的失效空线程应自动替换为可用的新线程。
- Agent 读取画布卡片：读取当前画布完成后，卡片应按非零类型显示文本、图片、配置、视频、音频、3D、分组、其他节点及连线数量，例如「3 个文本、5 张图片、2 个配置、1 个 3D、4 条连线」；空画布应显示「当前画布为空」，执行失败时仍应显示错误信息，刷新恢复历史后统计保持一致。
- Agent 首次发送响应：在空白新对话中输入内容并按回车后，输入框应立即清空、用户消息应立即出现在对话中，再显示「正在思考」；线程创建或发送失败时，原输入和附件应恢复；任务运行期间输入的新草稿不应在请求成功后被清空。
- Agent 动态工具信息：执行内置生图、查看图片、命令、文件修改或其他动态工具时，卡片标题应显示具体工具名称；执行失败时正文应显示真实错误原因，刷新并恢复历史对话后仍应保持一致，不再统一显示「工具操作已完成」。
- 打开 Bambu Studio：悬停已有模型的 3D 节点，工具栏在「导入 Blender」旁应出现「打开 Bambu Studio」。节点上已有 3MF 转换结果（3D 操作 → 转换格式 → 3MF）且本机装了 Bambu Studio 时，点击应走 `bambustudio://open?file=` 唤起 Studio，由 Studio 自行下载 3MF。优先用转换时记下的 Tripo 签名地址（和 Tripo / MakerWorld 自己的打开链接同形）；地址失效时需已连接 Canvas Agent，把本地 3MF 临时挂到 `http://127.0.0.1:17371/share/file/...`。没有 3MF 时应提示先转换，不要把 GLB/FBX 送过去。右键和多选工具栏应有同一项；多个节点依次唤起。空 3D 节点、图片、视频不应出现该按钮。未安装 Studio 时系统处理不了 `bambustudio://`，画布应提示无法唤起。这条路径不经过 Blender 的 WebSocket。
- Agent 画布生 3D：重启 Canvas Agent 后工作区 `AGENTS.md` 应包含 `canvas_generate_model3d`。输入「生成一个 3D 模型 / 椅子」时应调用该工具而不是 `canvas_generate_image`；对话卡片标题应为「生成 3D」。仅有提示词时应在画布上创建 3D 生成配置节点并立即运行（文生 3D）；先选中或提到已有图片节点时应把其 ID 放入 `referenceNodeIds`（1 张图生 3D，2–4 张多视图生 3D）。读取画布摘要应单独统计「N 个 3D」，不再把 3D 节点算进「其他」。Agent 应通过 `canvas_download_nodes` 触发画布媒体下载，并通过 `canvas_import_to_blender` 启动 Blender 导入；两者返回“已触发/已启动”而非虚构本地落盘路径或导入完成。
- Agent 画布生图：重启 Canvas Agent 后，其自动生成的工作区 `AGENTS.md` 应同步为最新版指令（用户自行编写的其他 `AGENTS.md` 不应被覆盖）；输入“生成一张图片”时应调用 `canvas_generate_image`，通过当前画布节点创建并运行生成流程；只有明确输入“使用 Codex 内置生图/ImageGen 技能生成”时才允许调用内置能力，Codex App Server 返回的 `imageGeneration` 结果应显示在对话中并作为保持原比例的图片节点添加到当前画布；Agent 不应在没有生成结果时提前声称“已生成”。
- Agent 顶部栏：在对话、历史和日志之间新增「技能」标签并显示已加载数量；连接状态应位于左侧 Agent 标题旁，并与右侧新对话使用相同规格的文字按钮，只有内容标签显示选中线；标签图标始终显示，中英文模式下都应按标签区域的实际可用宽度隐藏文字并保留小号数量，空间足够时显示图标和文字，拖动宽度时不应裁切、换行、横向滚动或错位。
- Agent 输入框窄屏布局：底部上传、Skill、确认模式、权限模式、模型和思考程度控件在窄面板下应只显示图标，宽面板下恢复文字；所有纯图标操作悬停时应使用统一样式显示名称或当前状态，任意宽度都不出现横向溢出。
- Agent 本地 Skill 管理：连接 Canvas Agent 后进入「技能」，应能读取当前 Codex 工作空间发现的项目、个人、系统和管理员 Skill，并支持搜索、按范围筛选、刷新及启停；未能加载的 Skill 应通过可点击、可滚动的详情查看原因；画布在站点工作空间 `.agents/skills` 下创建的 Skill 应可新建、编辑和删除，其他来源只读且不得被画布改写；编辑期间文件被其他窗口修改时应拒绝覆盖，清空显示名称、短说明和默认提示词后旧值应被删除，同时保留图标、品牌色等未由当前界面管理的元数据；多个标签页同时连接时，任一页面的 Skill 变更应自动同步，断开或切换 Agent 时旧请求不得重新写回列表或弹出编辑器。
- Agent Skill 草稿生成：创建 Skill 时应提供「空白创建」「从当前对话生成草稿」「从当前画布生成草稿」三种入口；空对话不得发起生成，取消时不得写入文件，确认后才写入站点工作空间 `.agents/skills`；Agent 运行中应禁用生成，多标签页下对话和画布来源必须分别严格绑定发起请求的 `threadId` 和 `clientId`，生成期间外部 MCP 仍应操作最近聚焦页面；草稿运行时创建、启停、删除和更新 Skill 应被统一拒绝，点击停止应真实中断临时草稿 turn；草稿不得泄露本地路径、密钥、媒体数据、真实节点 ID 或任务进度等临时状态，普通中文斜杠文本与 `/imagine` 等命令必须保持完整，生成草稿使用的临时 turn 不得出现在 Agent 对话、历史或日志中。
- Agent Skill 调用：在技能页点击「使用」或在输入框输入 `/` 搜索并选择 Skill 后，Skill 应作为原子 token 插入正文，而不是显示在输入框上方；发送任务时应通过 Codex 原生结构化 Skill 输入执行，发送成功后清除选择，失败时保留；新建对话、断开连接、Skill 被停用或删除时也应清除失效选择，发送前、任务完成后和刷新历史后的用户消息文字与 token 位置应保持一致。
- Agent 输入框快捷引用：输入 `/` 后应显示已启用 Skill 列表，输入 `@` 后应显示当前画布的图片、视频、音频和文本素材，长列表使用较高的内部滚动区域；选中项应按当前光标位置插入正文，例如「这是第一张图 `@图片1` 融合第二张图 `@图片2`」，不再集中显示在输入框上方，按 `Backspace` 或 `Delete` 时应整块删除；发送时应保持原句顺序，按节点 ID 精确引用发起页面的素材，并把引用图片的实际内容交给 Codex；输入框和聊天记录都应将引用渲染为与正文基线对齐的紧凑标签，悬浮或聚焦后可预览图片、视频、音频或文本内容，不重复显示内部图片附件，切换会话或刷新后引用样式应保持；可用方向键、`Enter` 或 `Tab` 选择，`Esc` 应关闭候选菜单，候选菜单打开时回车不得误发送消息。
- Agent 消息元数据：发送包含图片附件、Skill 或画布引用的消息后，刷新当前页面、在另一页面恢复同一对话或重启 Canvas Agent，历史消息都应由 Agent 按准确的 `clientMessageId`、`threadId` 和 `turnId` 恢复展示，本地缩略图仍可悬浮或点击查看，不依赖浏览器 IndexedDB 或文本匹配；通信协议版本变化不得清空独立的消息存储，遇到未知版本或损坏清单时应拒绝写入且保留原文件；删除线程后对应缩略图和引用元数据应同时删除，不得按记录数量或文件大小静默裁剪，改动前仅存在于浏览器旧缓存中的消息继续显示普通文本且不尝试迁移。
- Agent Markdown 样式：右侧 Agent 回复中的代码块应为横向占满消息区域、无语言标题和无双层边框的紧凑代码条，单行内容不应保留纵向大面积空白，复制操作仅在悬停时弱化显示；行内代码、链接在浅色和深色主题下应清晰；点击外部链接后应显示中文紧凑确认弹窗，长路径能够正常换行且复制、继续打开和关闭操作可用；点击 `/Users/`、`/home/` 等本地绝对文件路径时应改为提示在系统文件管理器中定位，支持复制路径，且浏览器地址不应跳转为 localhost 文件路径。
- Agent 工具确认模式：右侧面板标题栏不应再显示「工具确认」开关；对话输入框左下方应显示确认模式选择，默认选中「自动确认」，画布写入工具应直接执行；切换为「手动确认」后，画布写入工具应在对话中展示等待确认卡片，并支持批准或拒绝。
- Canvas Agent Codex 升级：启动 Canvas Agent 后应输出 Canvas Agent、内置 Codex 和本机 Codex 版本，实际运行的内置 Codex 应为 0.146.0；内置与本机版本不一致、未安装本机 Codex，或 npm 存在更新版本时应显示对应升级提醒，npm 检查失败不应阻止服务启动；Agent 应能正常连接 Codex、创建或恢复会话、发送消息并调用画布工具，运行中停止任务应只中断当前 turn，随后无需重启 Agent 即可继续发送新任务。
- Canvas Agent Debug：普通启动应通过公共 logger 输出 Info、Warn 和 Error 日志；使用 `npx -y @basketikun/canvas-agent@latest --debug` 启动后还应输出 Debug 日志并显示日志文件路径，终端统一采用“`YYYY-MM-DD HH:mm:ss` 级别 消息 详情”的纯文本单行格式，`~/.infinite-canvas/logs/` 下应按启动日期生成相同格式的 `canvas-agent-YYYY-MM-DD.log`，同一天多次启动应追加到同一文件；日志中不应出现连接 token 或图片 Data URL 原文。
- Canvas Agent 凭据脱敏：Codex 与 Claude CLI 的 stderr 包含 Bearer token、`sk-` 密钥、显式 API key/token/authorization 赋值、ANSI 样式或跨输出分片的凭据时，调试日志和网页诊断事件均不应出现明文；普通 stderr 文本应保持不变。
- Canvas Agent 配置权限：在 Linux 和 macOS 上保存配置后，`~/.infinite-canvas` 权限应为 `0700`，`canvas-agent.json` 权限应为 `0600`，已有的宽松权限也应被纠正；配置应能继续正常读写，Windows 启动不受影响。
- Canvas Agent URL 自动连接：链接应在 `#` 后传递 `agentUrl` 和 `agentToken`，进入或选择具体画布时继续保留，读取后立即从地址栏移除，并可连接有效的本机、局域网或远程 HTTP(S) Agent 地址且不主动展开设置面板；缺少参数或地址无效时应展开设置并显示错误。
- 图片 API 模型参数：`gpt-image-*` 的生成和编辑请求不应发送 `response_format`，`dall-e-*` 请求仍应发送 `response_format: "b64_json"`。
- 图片外链持久化：画布和生图工作台对图片接口返回的远程 URL 应只下载一次，经图片解码校验后保存到 IndexedDB；返回 `200` 但内容不是图片时应失败，下载期间停止画布生成后不得保存或应用结果；浏览器因 CORS 无法读取但图片仍可显示时，应保留原 URL 且不生成空 `storageKey`，插件调用在外链可读取时仍应收到 Data URL。
- 多参考图编辑：OpenAI 格式在多张参考图时应使用重复的 `image[]` 表单字段提交文件，单张参考图仍使用 `image`；新建的 OpenAI 图片脚本应使用相同字段名。Gemini 渠道和已经保存的自定义脚本不受影响。
- Canvas Agent Codex 日志：Codex app-server 输出带颜色或样式控制符及 UTC 时间的 stderr 时，本地日志和网页诊断日志应只显示一份 `YYYY-MM-DD HH:mm:ss` 本地时间和干净文本，不应出现重复 ISO 时间或 `[2m`、`[31m` 等 ANSI 转义内容。
- Agent HTTP 诊断日志：网页发送一条普通消息后，本地 Debug 日志不应重复输出 `/health`、`/canvas/state`、`/canvas/activate` 成功请求、流式增量或完整会话响应，只保留 HTTP 请求与 Codex 生命周期摘要；右侧「日志」应以单行时间线展示发送、开始、回复、工具、完成用量和错误，不再输出 userMessage started/completed、流式摘要、重复 threadId 或大段原始 JSON。
- Agent 排查日志：右侧「日志」中的排查视图应显示连接摘要，并可按错误、警告和信息筛选；向下查看日志时仅列表内部滚动，标题、连接状态、筛选数量和操作按钮保持固定；连续相同事件应折叠计数，单条日志可展开查看完整详情；原始 JSON、复制全部、复制最近错误和清空功能应继续可用，浅色与深色主题下均应清晰。
- Agent 排查日志顺序与跟随：日志应按时间从旧到新排列，进入日志或切换筛选时定位到最新事件；停留底部时自动跟随新日志，展开最后一条后应继续停留在完整详情底部，向上浏览后暂停跟随并显示与对话区视觉高度一致的居中圆形向下箭头，新日志数量只在悬浮提示中显示；列表底部不应出现额外留白，点击按钮后回到底部并恢复跟随。
- Agent 对话统计：用户消息应右对齐并使用透明无气泡的简洁排版，用户和 Codex 两侧均不显示人物头像，消息下方均不显示时间或 Token 信息；输入框上方应居中展示最新一次模型调用的输入、缓存、输出 Token 用量，不显示会话累计值，数值更新时应从旧值平滑滚动到新值而非突然跳变，新建、切换或删除当前会话后应清空旧统计。
- Agent 回复实时显示：在右侧 Agent 发送消息后，用户消息下方应立即出现“正在思考...”，任务运行期间不应闪退；工具完成后应显示 Codex 正在继续处理及已等待时长，等待超过 30 秒时提示可继续等待或停止本轮；Codex 的回复应在当前对话中持续显示，实时事件缺失时也应在任务完成后自动同步完整内容，无需切换到历史或日志再返回对话。模型繁忙等任务失败时应立即结束等待状态，在对话中显示中文错误原因和重试建议，诊断日志不应再把失败轮次记为“处理完成”，刷新历史后错误仍应保留。新建尚未发送首条消息的空会话不应反复出现历史读取失败。
- Agent 对话实时与历史一致性：运行包含思考、命令及画布工具的较长任务，在执行中刷新发起页面或打开第二个页面时，已出现的用户消息、思考过程、工具卡和回复前缀均应保留并继续更新；同一思考或工具只显示一张卡片，任务结束及再次刷新后内容、顺序和状态应一致。切换页面焦点不能改变本轮画布工具目标，发起页面断开后不得把图片或写操作转交其他画布，使用相同页面身份重连后才能继续处理。
- Agent 流式交互性能：发送长回复时文字应连续平滑出现，输入框、滚动和画布操作不应随回复变长而明显卡顿；长历史会话中只有当前流式消息持续更新，屏幕外消息不应造成明显布局压力；任务完成后应通过 SSE 自动同步完整历史，不再持续请求 `/health` 轮询状态。
- Agent 过程时间线：新建 Agent 对话后 Codex 应生成可读思考摘要，并在运行时依次显示中文的思考摘要、执行计划、命令执行、网页搜索、文件修改和画布工具活动；思考摘要的图标、标题和箭头应稳定保持在同一行，默认收起且无边框，点击箭头后才展开 Codex 实际返回的具体摘要，其中 Markdown 强调、列表和代码应正确渲染而非显示原始符号，多行代码块和文本流程图应保留原始换行并允许横向滚动，完成事件不应再用「已完成分析」覆盖已经收到的摘要；同一轮连续命令应合并为显示数量的无边框折叠行，折叠时不显示命令预览，单条展开后直接显示详情，多条展开后可逐条查看工作目录、耗时、退出状态和运行输出；其他工具调用继续使用紧凑卡片排版，状态图标、标题和状态文字保持在同一行；结构化任务进度不应混在对话时间线中，而应独立放在对话区下方、Token 统计上方，支持展开和折叠，并逐项实时更新「待处理」「进行中」「已完成」状态；新任务生成时默认展开，任务结束后保留最新结果，同一计划更新不应生成重复内容；文件详情展示文件路径与新增/修改/删除动作，工具详情不应出现请求 ID、英文工具名或原始 JSON；一轮对话结束自动同步历史以及刷新页面后从历史中 resume 对话时，思考摘要、命令和工具过程记录仍应完整保留并保持相同展示。
- Agent 权限控制：输入框可选择「请求批准」「自动审查」「完全访问」；请求批准模式下，Codex 编辑工作区外文件、执行受限命令或访问网络时应在对话中显示审批卡片，支持拒绝、允许一次和本会话允许，并能依次处理多个并发请求；提交决定后卡片应保持禁用等待，只有 Codex 确认处理后才移除；等待审批时刷新页面，未处理的审批卡应自动恢复且不能让任务永久卡住；自动审查模式应仅将需要用户决定的风险操作送入审批；完全访问必须先显示风险确认，启用后可访问网络和本机文件且不再请求审批；选择应在刷新后保留。
- Agent 历史记录：点击记录卡片应直接进入对应对话，不再显示「进入」按钮；可勾选单条或全选多条记录并批量删除，删除当前对话后聊天内容应清空。
- Agent 默认新对话：每次进入任一画布并连接 Agent 后，对话区应保持空白且不自动恢复上一次会话，并在后台创建新线程、预热 MCP；需要继续旧对话时可在「历史」中主动选择恢复。
- Agent 当前画布优先：在已打开某个画布时要求 Agent 创建、修改、整理或生成内容，Agent 应直接读取并操作当前画布，不应先调用 `canvas_list_projects` 或使用 `site_navigate` 重复进入画布；只有明确要求查看或切换其他画布时才允许查询画布列表并导航。
- Agent 图片消息：发送一张或多张图片附件后，图片应紧跟用户文字并在消息右侧显示为约 40px 的紧凑缩略图，不再撑大消息区域，单击缩略图应打开大图预览，打开或关闭预览不应改变消息间距或产生额外空行；任务运行中、完成同步历史、切换页面及重新进入历史对话后都应显示浏览器本地保存的图片缩略图，不应消失或把 attachmentId、附件使用说明等内部上下文回显到用户消息中；删除历史会话后应同步清理对应缩略图。
- 画布文本复制：在 Agent 对话或节点信息详情中用鼠标选中文字后，按 `Ctrl/Cmd + C` 应复制所选文本，不应触发画布节点复制；未选中文字且焦点位于画布时，原有节点复制快捷键应保持可用。
- Agent 工作目录指令：`canvas-agent/agent-instructions.md` 应作为独立维护源；重启 Canvas Agent 后，当前工作目录应自动生成 `AGENTS.md`；新建对话发送消息时，Codex 日志中的用户消息只包含本轮请求和必要的附件上下文，不再重复整段 Infinite Canvas 前置提示词，画布及工作台工具仍可正常调用。
- 画布文本设置：文本节点和生成配置节点切换到文本模式后应显示推理强度设置，可选择自动、低、中、高、极高；选择自动时默认 OpenAI Responses 请求不应携带 `reasoning`，选择其他档位时应携带所选强度，刷新画布后节点设置应保留；文本模型自定义调用脚本应能读取 `reasoningEffort`，OpenAI 模板应按自动或指定档位正确组装请求。
- 生图工作台参考图：将一张或多张图片拖入参考图区域后应直接上传并显示缩略图；拖入非图片文件应忽略，拖动过程中区域应显示高亮提示，放下文件不应导致浏览器打开或替换当前页面。
- 工作台历史图片清理：生图或视频工作台生成内容后，在「我的素材」删除图片、删除画布图片节点、清空画布或删除画布，再次打开对应生成记录时，历史缩略图、结果图片和参考图仍应正常显示；删除生成记录时，其专属本地文件仍应正常清理。
- 视频创作台参考资产：将图片、MP4/MOV 视频或 MP3/WAV 音频拖入任一参考资产区域后，应按文件类型自动上传到对应列表；当前拖入区域应显示高亮提示，原有数量、大小、时长和格式限制应继续生效。
- 画布组装提示词：输入或连接超长提示词后，浮层正文高度不应继续撑大，内容应可在正文区域内滚动查看和编辑，标题及关闭按钮保持可见。
- 画布节点提示词：图片等节点下方的提示词超过输入区域高度后，鼠标悬停在输入区域内滚动应查看提示词内容，不应缩放画布。
- 画布节点提示词回显：单图或多图生成完成后，切换选择生成结果的根节点及任一子节点，下方输入区域都应继续显示生成时的提示词；切换到其他节点再选回来后也不应清空。
- 画布生成配置：连接文本节点后连续点击生成（包含失败重试），组装提示词不应重复追加上游文本；在生图、文本、视频、音频之间切换时，实际请求应始终使用当前面板展示的对应类型模型。
- 画布多图生成：开始生成 N 张图片后应立即创建一个包含 N 个可展开槽位的图片节点，并且来源到结果只保留一条连线；生成期间空槽位应独立显示生成中或失败，任何已有图片内容的槽位都必须始终显示图片，任意图片率先成功后应立即成为主图并展示，不等待其他请求完成；收起状态应最多显示三层紧密错开的背板，避免占用过多画布空间，右上角应显示醒目的「N 张」数量提示；点击数量后，浮动工具条应暂时隐藏，各图片槽位应从当前节点向右上方整齐展开；已成功图片的「设为主图」应常驻显示，并在亮色、深色主题及不同图片背景上保持清晰；点击画布空白处应自动收起并恢复工具条。
- 画布多图主图切换：点击「设为主图」后，节点中心和当前最长边应保持不变，仅按新图片比例调整另一条边；自由变形节点应完全保持现有宽高，画布视口及左下角缩放值不应变化。
- 画布多图失败槽位：包括当前主槽位在内的每个失败槽位都应显示「重试」和「删除」；重试只更新当前槽位，已有成功主图时不得抢占主图；删除只移除当前失败槽位并同步更新图片数量。
- 画布多图尺寸调整：子图展开时开始拖动尺寸控制点，应先收起图片组一次，再正常调整根节点尺寸，不应触发 React 循环更新或应用错误页。
- 画布左侧元素列表：点击元素整行应平滑定位并选中对应节点，自动缩放不得超过 100%；有内容的图片元素应显示预览按钮，点击后打开大图弹窗且不触发画布定位。
- 配置与用户偏好：导出 JSON 后应包含渠道、默认模型、生成偏好、提示词来源和 WebDAV 配置；在修改当前配置后重新导入该文件，应恢复导出时的设置，错误 JSON 文件应提示格式不正确。配置文件包含 API Key 和 WebDAV 凭据，不应公开分享。
- WebDAV 画布删除同步：将已同步到 WebDAV 的画布在本地删除后再次点「立即同步」，该画布不应从远端恢复到列表；刷新页面后再同步，已删除画布也不应回来。另一台设备新建且未删除的画布同步后仍应出现。我的资产和生成记录的删除同步不在本次范围。
- 本地存储设置：配置页应显示「本地存储」Tab，进入后只读取 `infinite-canvas` 数据库，自动统计 IndexedDB 占用、站点总占用、浏览器配额与使用率，并按对象仓库显示记录数及内容体积；新增或删除图片、音视频、生成记录后点击刷新，数据应同步变化，统计期间页面保持可操作。
- 生成提示词的文本编号：普通节点或生成配置连接多个文本节点后发起生成，附加在提示词末尾的每段上游文本都应以「【文本1】」「【文本2】」开头并按连接顺序编号，编号与提示词里 `@` 引用及参考内容栏显示的一致；单段文本同样要带编号，图片、视频、音频编号不受影响。
- 局部遮罩编辑：弹窗底部应为「重置」「导出到画布」「立刻生成」；两个按钮都要求已涂抹区域并填写修改要求，「导出到画布」只写入节点和连线不发起请求，结果节点的提示词面板应预填拼好的提示词并可手动生成，「立刻生成」在写入节点后立即生成。涂抹区域并填写修改要求后确认，画布应在原图下方生成一个「遮罩标注」图片节点，内容为原图叠加半透明蓝色标注区域，颜色和透明度应与弹窗里涂抹时看到的一致；结果节点在原图右侧生成，并同时接收来自原图和遮罩标注的两条连线。请求应按普通参考图发送两张图片，提示词按「图片1 / 图片2」编号说明原图和标注区域，不再携带 mask 参数，Gemini 格式渠道也应可用；生成结果只改动标注区域，且不得残留蓝色标注。
- 图片编辑弹窗：遮罩、切图和裁剪连续滚轮缩放时，图片与遮罩应保持同步且不再闪烁、短暂消失或跳动；遮罩画笔圆心应始终固定在鼠标位置，仅直径随缩放变化，缩放后仍可准确涂抹、拖动切分线和调整裁剪框。
- 提示词中心布局：页面标题及提示词总数应居中；连续输入搜索文字时应在停止输入约 300ms 后再查询；桌面端分类与标签应在左侧独立滚动，右侧搜索框下直接展示提示词卡片；标签数量较多时不能继续向下挤压提示词，窄屏下应恢复上下排列且内容不溢出；不再显示「我的提示词」Tab，收藏提示词应直接加入我的资产。
- 提示词详情弹窗：封面和参考图应固定显示在上方，复制及加入资产操作栏固定在底部，只有中间的标签、描述及提示词内容区域可以滚动；弹窗宽高应受视口限制且不超出屏幕。
- 提示词来源：7 个内置来源应从 Image Prompts 统一仓库读取，更新后数量依次为 323、494、517、53、76、126、129；提示词仍按 7 个来源分组并可独立启用，来源内可继续按 `tags` 筛选。添加标准 JSON URL 后应能查看内容，填写非数组 JSON 或不可访问地址时应显示失败，并继续保留该来源上一次成功缓存的内容。
- 提示词来源界面：来源应以卡片列表展示，启用开关位于左侧，数量、同步状态和上次成功时间作为次级信息显示，查看、拉取及自定义来源编辑/删除操作使用带文字按钮；底部定时拉取区域应保持独立边框布局。
- 画布提示词库：不应再显示「我的提示词」分组；不展开任何公共来源直接搜索其中的提示词，匹配项应自动显示；点击「插入画布」后应创建正文正确且标题保持为提示词标题的文本节点。
- 全站 Agent：新增 `generation_get_status` 工具，画布生成节点可按 `nodeIds` 查询，生图和视频工作台提交后会返回 `taskId` 并可查询排队、运行、成功或失败状态；需验证查询只由当前活动标签页返回。
- 本地 Agent 多标签页隔离：同时打开两个不同画布并连接同一个 Agent，分别聚焦标签页后通过 MCP 读取和修改画布，操作应只落在当前聚焦页面；网页面板发起的整个 Codex turn 应固定操作发起页面，即使中途聚焦另一标签页也不能切换目标；非运行状态关闭当前页面后应回退到最近聚焦且仍连接的页面，运行中关闭发起页面则不得把操作转交其他画布，只有同一页面身份重连后才能继续；其他页面回传同一请求结果应被拒绝。
- 本地 Agent 多标签页会话同步：所有标签页共享同一个站点级 Codex 活跃线程；任一页面发送消息、新建、恢复或删除会话后，其他页面应同步活跃线程和聊天记录；Agent 输出仅显示在事件所属线程，运行中不能新建、恢复、删除或再次发送任务。
- 本地 Agent 运行状态同步：在一个标签页运行较长 Codex 任务，等待某张工具卡显示「工具完成」后再打开或刷新第二个标签页；第二个标签页应立即显示 Codex 正在运行并禁用发送，整轮结束后两个标签页同时恢复；工具卡只显示「工具完成」，整轮结束由「本轮完成」表示。
- 本地 Agent 图片附件落画布：在右侧 Agent 上传参考图并要求基于商品信息创建生图流程，附件应创建为保持原比例的真实图片节点，分析提示词应创建为文本节点，二者都应连接到生成配置节点；刷新页面后参考图仍可显示并参与生成。任务中途切换到其他标签页时，附件只能写入发起任务的标签页；若发起标签页关闭，附件读取应失败且不能落入其他画布。
- Agent 对话滚动：从历史或日志切回对话、恢复其他会话时应自动定位到最新消息；手动向上浏览后应显示与日志完全相同尺寸、位置和样式的居中圆形向下箭头，新消息不强制打断阅读，对话底部不应出现额外留白，点击按钮后平滑回到底部并继续跟随新消息。
- Agent 消息区分：用户消息应在右侧使用透明无气泡排版，AI 回复应在左侧使用无头像的开放式 Markdown 排版；长文本、多张附件、错误消息及浅色/深色主题下均应清晰且不溢出。
- Agent 命令记录：命令执行中应显示运行状态；完成后，同一轮相邻命令应合并为「已执行 N 条命令」折叠行且默认不显示原始命令，单条展开后直接显示完整详情，多条展开后可分别查看命令、输出和退出状态；对话结束或刷新后分组与记录不应消失。
- 跨域提示：生图、视频或音频请求被浏览器跨域策略拦截时，应明确提示需要通过自己的服务转发请求，不再只显示笼统的网络错误。
- 资产图片下载：我的资产中仍可预览的图片，点击「下载图片」应能保存文件；标题含中文、空格或「【】」时应沿用原标题作为文件名，无需改名；从画布刚存入、尚未刷新页面的图片也应能下载。
- 画布视频任务恢复：开始 OpenAI 风格视频生成后，视频节点应保存远端任务 ID。刷新页面后，尚未完成的视频应自动继续查询状态；若查询已停止，可点击「获取任务状态」继续用该任务 ID 拉取，直到生成成功、任务失败或查询请求报错。任务失败后，「重试」应重新发起生成而不是继续查旧任务。
