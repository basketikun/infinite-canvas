# coocaa 内容生产平台阶段工作汇报

> 汇报口径：在 happywork 留痕，按“我的目标、当前 GAP 与核心卡点、AI 原生解决路径、当前推进进度”四个维度汇报。

## 一、我的目标

### 项目介绍与产品定位

酷开智影·Coocaa SmartVid 平台是一个**面向业务内容生产**的 AI 平台，不是单一的视频生成器，也不以替代现有剪辑系统为目标。选择 Codex App 作为 Agent 基座，复用其成熟的任务规划、工具调用、Skill、MCP、审批、会话与执行轨迹能力；平台在其上建设模型适配与模块化工作流编排能力，根据脚本策划、多模态理解、视频生成、质量审核等任务选择合适模型，避免业务工作流绑定单一模型或供应商。

平台沉淀素材与版权、内容标签、内容版本、正片关联和工作流执行记录等公共能力。投放实验、转化归因和用户反馈由推荐、运营及数据平台提供；SmartVid 接收这些数据，并将其转化为对各工作流模块的选题、脚本、编排、标签和版本策略的优化输入。每个内容方向以独立工作流模块接入。影视解说是首个模块，用于验证“内容 -> 正片 -> 权益 -> 支付”的商业闭环；后续可扩展亲子、科普、节目预告等模块，共享平台能力而不重复建设。

```txt
Codex App Agent 基座
  └─ 任务规划、工具调用、Skill、MCP、审批、会话与执行轨迹
          ↓
内容生产平台公共能力
  ├─ 模型适配、素材与版权、标签与正片关联
  ├─ 内容版本、模块工作流与执行记录
  └─ 基于外部数据的工作流优化
          ↓
模块化工作流
  ├─ 影视解说创作（首个验证模块）
  ├─ 亲子内容创作
  ├─ 科普内容创作
  └─ 其他垂类内容工作流
          ↓
推荐、运营及数据平台
  ├─ 内容投放与实验执行
  ├─ 转化归因与用户反馈采集
  └─ 效果数据回流 SmartVid，优化工作流模块
```

### 核心价值出口

以 AI 持续生产 coocaa 自有影视解说内容为载体，形成从内容供给、正片消费到商业转化的价值链。当前先跑通引流转化，再扩展片库经营、用户意图协同、会员留存和深度内容付费；平台最终沉淀的不是单条视频，而是可复用的内容工作流、内容资产和持续优化能力。

#### 出口一：引流转化（当前核心）

用高质量影视解说吸引用户进入内容，再通过解说与正片的精确关联，驱动正片起播、权益页跳转和下单。每条解说内容都绑定对应正片 ID、跳转入口和独立标签，使其从“内容”变成可追踪、可归因的转化入口：

```txt
自有影视解说 -> 正片详情页 -> 正片起播 -> 权益页 -> 下单/SDK 支付
```

| 核心指标 | 计算方式 |
| --- | --- |
| 解说 -> 正片跳转率 | 从解说内容跳转至正片详情页的用户数 ÷ 解说内容有效播放用户数 |
| 跳转 -> 正片起播率 | 跳转后起播正片的用户数 ÷ 跳转用户数 |
| 跳转 -> 权益转化率 | 跳转后进入权益页并下单的用户数 ÷ 跳转用户数 |

这条链路跑通后，短视频创作智能体不只是生产内容，而是在生产可量化、可归因的转化入口，并为 SDK 支付 GMV 增量提供可追踪的贡献。

#### 出口二：付费内容包（阶段二储备）

将高质量深度影视解说沉淀为可付费的内容资产，例如完整拉片、导演作品体系解读和类型影史分析。在大屏场景中，“充电”不采用单次打赏模式，而定位为权益体系内的频道或内容包订阅，复用现有会员和 SDK 支付链路。

出口二只面向“值得付费”的深度内容，不以普通解说替代会员内容。它建立在出口一之上：先用广覆盖的解说验证引流与转化，再从高意愿用户中孵化深度内容的订阅需求。

```txt
短视频创作智能体 -> 自有影视解说内容
                      ├-> 出口一：引流正片起播与权益转化
                      └-> 出口二：深度解说付费内容包
                                       ↓
                               SDK 支付 GMV 增量
```

#### 三个可扩展的价值出口

这三个方向不是额外堆功能，而是分别解决存量资产利用、推荐决策和用户长期价值问题：

| 方向 | 价值机制 | 关键验证指标 | 优先级 |
| --- | --- | --- | --- |
| **片库再经营** | 用解说重新包装长尾电影、剧集和专题，让已购买或已授权的片库持续获得新的正片入口 | 长尾正片起播增量、片库激活率、单部版权内容观看时长、单位版权成本带来的消费增量 | P1，与出口一共用链路 |
| **用户意图数据协同** | SmartVid 输出内容标签、版本和正片关联；推荐与数据平台结合完整观看、跳转、点赞和不喜欢等行为形成推荐信号，结果再回流优化工作流 | 曝光 -> 播放、完播率、跨天回访、正片起播的对照组提升，以及负反馈后的推荐纠偏效果 | P2，随阶段一建立数据回流 |
| **会员留存内容服务** | 通过“每周导演馆”“悬疑片深度解读”等系列内容，持续创造用户打开电视、停留和续费的理由 | 活跃天数、D7/D30 留存、会员续费率、流失用户召回率、会员人均观看时长 | P3，在供给稳定后放大 |

### 做到什么程度

1. **最小可行验证**：选定一个影视主题，用 AI 辅助生产 5–10 条影视解说内容；每条内容绑定正片 ID、跳转入口和自有标签，投放短视频 TAB，验证播放、留存，以及“解说 -> 正片 -> 权益”的转化链路不低于同类外部内容。
2. **半自动化生产**：跑通选题、素材搜索、高光片段识别、剪辑编排、标签标注、质量检查和人工审核流程；在出口一稳定后，筛选适合深度解说内容包的主题。
3. **全自动化生产**：由 Agent 根据内容策略自主判断选题、生成内容、校验质量和产出多种发布版本，人只做关键节点审核、抽检和异常处理。
4. **运营平台供给**：形成可被自动化运营平台直接调用的内容生产 Skill，持续供给自有内容资产，并逐步孵化权益体系内的深度解说内容包。

| 程度 | 验收标准 |
| --- | --- |
| 最小可行验证 | 完成 5–10 条内容投放，播放和留存不低于同类外部内容，且“解说 -> 正片”跳转链路可追踪 |
| 半自动化 | 选题 -> 素材 -> 剪辑 -> 标签 -> 审核流水线跑通；单条内容从选题到上线的耗时形成基线并持续缩短 |
| 全自动化 | Agent 可自主选题和生产，人工抽检比例逐步下降，内容质量通过率达到阶段性目标 |
| 运营平台供给 | 内容资产、标签、版本和效果数据自动进入内容池，可被推荐系统和运营平台通过 Skill 调用 |

> 半自动化的单条上线时长、全自动化的人工抽检比例和质量通过率，统一在阶段一建立真实基线后确定目标值，不预先填入未经验证的数字。

## 二、当前 GAP 与核心卡点

### 与目标的差距

- coocaa 短视频频道目前缺少自有内容资产，内容供给主要依赖爱奇艺、腾讯、B 站等外部平台。
- 短视频创作智能体尚未搭建，从素材搜索到剪辑、审核、发布和标签标注的全链路还未跑通。
- 自有内容标签、正片关联 ID 和跳转归因链路尚未建立，推荐系统难以区分自有影视解说与外部内容，也无法稳定匹配用户兴趣和追踪转化效果。
- “点赞”“不喜欢”等显式反馈尚未稳定回流到 SmartVid，工作流无法依据真实效果持续优化选题、剪辑、标签和版本策略。
- 片库长尾内容的激活率、内容带来的用户意图协同效果和会员留存价值尚未建立独立的度量口径。

### 当前业务基线

当前 coocaa 电视基本大盘的 SDK 营收转化漏斗可作为后续验证的业务基线：

| 漏斗环节 | 当前值 |
| --- | ---: |
| 开机 | 100% |
| 主页到达 | 78% |
| 内容曝光 | 52% |
| 内容播放 | 35% |
| 权益页跳达 | 12% |
| 下单 | 5% |
| SDK 支付成功 | 4.2% |

阶段一会由推荐、运营及数据平台提供“解说有效播放 -> 正片详情页 -> 正片起播 -> 权益页 -> 下单/支付”的归因结果，SmartVid 据此验证播放、留存、正片跳转和内容版本效果，不直接把内容播放数据等同于 SDK 支付结果。

### 关键卡点

1. **外部内容源受制于人**：外部平台标签标准不统一，供给、更新节奏和运营方式不受控，原生短视频与影视综高能片段混在一起，难以针对性推荐。
2. **外部效果数据尚未回流工作流**：点赞、不喜欢等显式反馈以及播放、留存、转化结果尚未形成稳定的数据接口，SmartVid 无法据此优化选题、剪辑、标签、标题和推荐理由策略。
3. **自有内容缺少独立标识和结构化交付契约**：影视解说内容如果没有独立标签、正片关联 ID、跳转入口、内容版本和分发字段，容易和外部内容混淆，也无法被推荐、运营及数据平台准确投放、归因和回传效果。
4. **生产链路还没有跑通**：媒资检索、人物和场景识别、高光片段理解、剪辑编排、音乐匹配、质量检查和多版本发布尚未形成可执行流水线。
5. **跨平台数据和接口契约待确认**：需要明确影视素材库访问权限、镜头级索引、标签字段、SmartVid 的结构化内容交付格式，以及短视频 TAB 投放、归因结果和用户反馈数据的回流口径。
6. **影视素材版权和使用权限不明确**：Agent 需要从影视库中搜索和剪辑素材，但素材库访问权限、镜头级索引和二次创作使用边界尚未确认，这直接影响多模态素材搜索、高光片段理解和专业剪辑编排三项核心能力的验证。

## 三、AI 原生解决路径

### 怎么解决

建设一个“主题驱动、外部数据回流优化”的视频创作 Agent。它不是传统的“人写好脚本、AI 帮忙生成”，而是由 AI 主导从内容策略到结构化内容交付的连续决策；推荐、运营及数据平台负责执行投放、归因和反馈采集，SmartVid 消费结果数据并持续优化工作流：

```txt
内容策略 / 外部效果数据
          ↓
AI 选题与素材理解
          ↓
脚本、剪辑、音乐、标签与多版本生成
          ↓
结构化内容交付：内容 ID、版本、标签、正片关联
          ↓
推荐、运营及数据平台：投放、归因与反馈采集
          ↓
效果数据回流 SmartVid -> 优化选题、编排、标签与版本策略
```

AI 的核心职责是把“什么内容值得生产、如何表达、以什么内容版本交付、如何根据效果持续改进”串成可迭代的闭环；“给谁看、如何投放、如何归因”由推荐、运营及数据平台负责。人的职责按阶段逐步收敛：早期负责目标和边界、素材权利、关键节点确认和发布审核，流程稳定后转为抽检、异常处理和策略校准。任何正式上线内容仍需通过合规和发布审批。

### AI 主导的内容生产闭环

| 环节 | SmartVid / Agent 负责什么 | 必须沉淀或交付的结果 |
| --- | --- | --- |
| 策略与选题 | 根据栏目目标、片库供给和外部效果数据判断主题、内容形态与预期出口 | 选题理由、目标内容场景、预期出口、优先级 |
| 素材理解 | 搜索影视库，识别人物、场景、剧情节点、经典台词和高光片段 | 素材来源、正片 ID、时间码、人物/场景/主题标签 |
| 内容编排 | 生成解说脚本、分镜、旁白、字幕、音乐和 1–5 分钟大屏剪辑 | 可审片版本、内容标签、合规检查结果 |
| 版本与结构化交付 | 批量生成不同时长、标题、推荐理由和封面版本，绑定正片 ID 与跳转入口 | `contentId`、版本号、标签、正片跳转入口和交付字段 |
| 效果驱动优化 | 接收外部平台返回的播放、留存、点赞、不喜欢、跳转、起播、权益和支付结果，判断内容是否有效 | 内容效果报告、工作流优化输入、下一轮策略调整 |

这条闭环直接承接三条任务线：

| 任务线 | 在产品中的位置 | 阶段性产出 |
| --- | --- | --- |
| 与张起凡配合，用 AI 优化推荐算法逻辑 | 推荐算法协同与数据回流层 | 内容标签、内容特征、版本信息及外部实验结果的协同使用 |
| 利用 AI 批量生成与优化海报标题、推荐理由 | 内容生产与结构化交付层 | 多版本标题、推荐理由、封面及可供外部投放的内容包 |
| 深入研究并实践纯 AI 做千人千面的落地方案 | 系统主线与工作流编排层 | 从选题、生产、结构化交付到效果数据回流优化的自动化闭环 |

第三条任务线是平台主线，第一条保持同步，第二条作为可复用的内容生产配套能力接入；三条线共同服务于内容生产平台，而不是三个相互独立的功能项目。

### 七项核心能力

| 能力 | 说明 |
| --- | --- |
| 主题与内容场景判断 | 根据内容策略、片库供给和外部效果数据选择主题、内容场景与预期价值出口 |
| 多模态素材搜索 | 从影视库搜索匹配的影片片段、画面和音效，并保留素材来源与版本信息 |
| 人物、场景与高光理解 | 识别角色、关系、场景、关键剧情节点和经典台词，形成可剪辑时间码与标签 |
| 专业剪辑编排 | 按大屏短视频 1–5 分钟的节奏编排叙事、旁白、字幕、音乐和转场 |
| 内容质量与合规检查 | 自动检查画面质量、音画同步、字幕一致性、素材权利和内容合规 |
| 多版本生成与结构化交付 | 生成不同时长、标题、推荐理由和封面版本，绑定正片 ID、跳转入口、标签和版本信息，支持外部系统投放与归因 |
| 反馈驱动的工作流优化 | 接收外部平台的播放、留存、正负反馈、起播和支付结果，更新内容标签和生产策略 |

### 具体计划

| 阶段 | 目标 | 核心动作 |
| --- | --- | --- |
| 阶段一：最小可行验证 | 证明 AI 能产出用户愿意看、愿意跳转正片的影视解说内容 | 选定一个影视主题，AI 生产 5–10 条内容，绑定正片 ID、标签和跳转入口，向短视频 TAB 交付内容包，验证播放、留存、跳转和起播 |
| 阶段二：半自动化 | 建立“AI 生成 + 人工审核”的稳定流水线，并接入第一版效果数据回流 | 跑通选题、素材搜索、高光识别、剪辑、标签、标题/推荐理由批量生成、质量检查和审核上线；根据外部效果数据优化工作流，筛选深度解说内容主题 |
| 阶段三：全自动化 | Agent 独立完成内容生产、版本生成和持续优化 | Agent 自主判断选题、生成内容、校验质量、生成多版本并依据外部效果数据调整，人做抽检和异常处理 |
| 阶段四：平台化供给 | 成为推荐和运营平台的结构化内容供给端，并验证第二个内容模块 | 自动交付内容资产、标签、正片关联和版本结果；沉淀模块接入规范，验证亲子或科普等第二个工作流模块 |

**阶段一 -> 阶段二的跃迁条件**：阶段一验证通过，即播放和留存不低于同类外部内容，且“解说 -> 正片”跳转链路可追踪；或验证未通过但已经明确问题来自选题方向、内容质量或投放策略，并完成修正方案。未满足任一条件时，继续留在阶段一迭代，不直接进入半自动化建设。

首期仍会复用现有无限画布、Canvas Agent、视频节点和 Skill 机制，但画布承载的不再只是粗剪过程，还要记录选题、素材、标签、版本和外部效果数据对应的优化记录。投放、归因和反馈采集不在 SmartVid 内部实现，而是通过明确接口与推荐、运营及数据平台协同。外部影视片段必须来自具备使用权限的素材库；外部平台内容只作为选题和叙事参考，不自动下载、搬运或重新发布。

## 四、当前推进进度

### 已完成事项

- 已完成酷开智影·Coocaa SmartVid 平台的初步搭建：已有无限画布、文本/图片/视频/音频等内容节点、多模型生成配置、Canvas Agent 与 Codex App 的 MCP 连接、Agent 会话及 Skill 管理，可承载内容工作流的可视化编排和执行。
- 已与产品负责人对齐短视频业务目标和底层逻辑。
- 已明确“做大 coocaa 自有短视频内容”的方向。
- 已与产品同事对齐，任务明确为“建设短视频创作智能体”。
