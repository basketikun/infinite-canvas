# 后端控制平面

`server/` 恢复 v0.3.0 的账号、权限、积分、模型代理、提示词、公共素材、参考媒体和系统设置 API。配套 Compose 同时启动新版 Vite 画布、Go 控制平面和旧版独立管理台。

画布项目和其引用的本地媒体可选择同步至服务端；个人素材与生成记录继续由浏览器 IndexedDB/WebDAV 管理。云同步与 WebDAV 是互不替代的两种同步目标。

## 本地运行

```bash
cp server/.env.example server/.env
cd server
go test ./...
go run .
curl http://127.0.0.1:8080/api/health
```

## Docker

```bash
cp server/.env.example server/.env
docker compose -f docker-compose.control-plane.yml up --build
```

启动后访问：

- 画布：`http://127.0.0.1:3000`
- 控制平面：`http://127.0.0.1:8080/api/health`
- 管理台：`http://127.0.0.1:3001/login`

画布设置中可以保持「本地直连」而无需登录；切换为「服务端」后，使用控制平面账号登录，模型和供应商 API Key 始终只保存在后端管理设置中。

上线前需要替换管理员密码与 JWT 密钥，并把 `CORS_ALLOW_ORIGINS` 配置为实际画布来源。`CONTROL_PLANE_URL` 是浏览器访问控制平面的公开地址，不能填写 Compose 内部主机名 `control-plane`；单域名反向代理时，它必须是域名根地址，**不能附加 `/api`**，否则前端会错误请求 `/api/api/*`。

```bash
CONTROL_PLANE_URL=https://canvas.example.com \
docker compose -f docker-compose.control-plane.yml up --build -d
```

同时将 `server/.env` 中的 `PUBLIC_BASE_URL` 和 `CORS_ALLOW_ORIGINS` 改为对应公开 URL。部署配置中不应写入供应商 API Key、用户 JWT 或管理台密码。

## 可选云同步

云同步使用独立 PostgreSQL 与 MinIO/S3，不改变 WebDAV。先复制云同步环境模板并替换其中每一个示例密码、域名与密钥：

```bash
cp server/.env.cloud.example server/.env.cloud
# 编辑 server/.env.cloud：特别是 ADMIN_PASSWORD、JWT_SECRET、POSTGRES_PASSWORD、MINIO_ROOT_PASSWORD
docker compose --env-file server/.env.cloud \
  -f docker-compose.control-plane.yml -f docker-compose.cloud-sync.yml up --build -d
```

`--env-file server/.env.cloud` 必不可少：控制平面、PostgreSQL 和 MinIO 都读取同一份部署变量。不要把 `server/.env.cloud` 提交到 Git。

在画布「配置与用户偏好 → 同步」中选择「云同步」，登录服务端模式后可以：

- 顺序提交所有本地画布和其引用媒体；每个画布使用独立 revision；
- 查看并显式恢复云端项目，下载媒体会做 SHA-256 校验；
- 发生 409 时选择「用本地覆盖远端」「使用远端」或「另存本地副本」。

云同步不会同步 WebDAV 的资产和生成记录；需要这些内容跨设备时，继续单独使用 WebDAV。

### 双浏览器验收

在云同步 Compose 已启动后，可用一次性 Playwright 容器执行真实双会话验收（不会写入项目依赖）：

```bash
docker pull mcr.microsoft.com/playwright:v1.54.0-noble
docker run --rm --network host \
  -e BASE_URL=http://localhost:3000 -e API_URL=http://localhost:8080 \
  -e E2E_USERNAME=admin -e E2E_PASSWORD='<你的管理员密码>' \
  -v "$PWD/scripts/cloud-sync-browser-e2e.mjs:/work/cloud-sync-browser-e2e.mjs:ro" \
  mcr.microsoft.com/playwright:v1.54.0-noble sh -lc \
  'mkdir -p /tmp/e2e && cp /work/cloud-sync-browser-e2e.mjs /tmp/e2e/e2e.mjs && cd /tmp/e2e && npm install --no-save --no-package-lock playwright@1.54.0 >/dev/null && node e2e.mjs'
```

该脚本使用两个隔离浏览器上下文，覆盖本地同步、远端恢复、媒体写入 IndexedDB、409 冲突的副本/远端/本地覆盖操作。生产域名必须让 `CORS_ALLOW_ORIGINS` 包含实际画布来源，并将 `BASE_URL`、`API_URL` 改为对应 HTTPS 地址。

## 生产发布与回滚

开发 Compose 会本地构建镜像；生产应使用 tag 发布工作流生成的三套同 SHA 镜像。发布前将 `IMAGE_OWNER` 设为 GitHub 用户或组织、`IMAGE_TAG` 设为完整 Git SHA，并准备真实的 `server/.env`：

```bash
IMAGE_OWNER=timerainv7 \
IMAGE_TAG=<完整 Git SHA> \
CONTROL_PLANE_URL=https://image.example.com \
docker compose --env-file server/.env -f docker-compose.release.yml up -d
```

生产 Compose 内置 Nginx 网关，唯一监听 `127.0.0.1:3002`。Cloudflare Tunnel 只需将公开域名转发到 `http://127.0.0.1:3002`：

```text
https://image.example.com/       -> 新版画布
https://image.example.com/api/*  -> Go 控制平面
https://image.example.com/admin  -> 管理台
```

对应的 `server/.env` 至少应设置：

```dotenv
PUBLIC_BASE_URL=https://image.example.com
CORS_ALLOW_ORIGINS=https://image.example.com
```

云同步生产部署再叠加 `-f docker-compose.cloud-sync.yml` 并把 `--env-file` 改为 `server/.env.cloud`。发布前备份 PostgreSQL 卷或数据库、检查 `https://image.example.com/api/health` 与 `https://image.example.com/admin` 登录；回滚时只把 `IMAGE_TAG` 改回上一 SHA 后重新 `up -d`，不要执行 schema downgrade。
