# 酷开媒资：从片名检索到本地原片

本文记录一条已经端到端验证的流程：输入片名，定位专辑和单集，确认媒资服务中的下载状态，并将已准备好的原片保存到本地。

适用范围：电影、电视剧、综艺等酷开媒资。本文只使用酷开媒资接口，不依赖其他项目的业务接口、任务表或调度服务。

## 1. 流程总览

```text
片名
  -> v4.0 搜索得到专辑候选
  -> GET 分集列表得到某一集的 coocaa_m_id
  -> 查询下载状态，取得规范化 coocaaVId/coocaaMId 和 mediumUrl
  -> 未就绪时发起下载任务并轮询
  -> 重新读取 mediumUrl
  -> HTTP 下载到本地 MP4
```

关键原则：搜索结果的 `id`、分集对象的 `id`、`third_id` 和 `coocaa_m_id` 不是同一个概念。下载接口只接受 `coocaaVId` 和 `coocaaMId`，不能靠猜测或用 `third_id` 代替。

## 2. 接口清单

| 阶段 | 方法和地址 | 是否有副作用 |
|---|---|---|
| 搜索影片 | `GET https://movie-tc.skysrt.com/v2/search/v4.0` | 否 |
| 获取分集 | `GET https://demo-media.skysrt.com/v2/getVideoSegmentList` | 否 |
| 查询下载状态 | `GET http://106.53.102.240:6003/require/obtainMovieDetail` | 否 |
| 发起媒资下载 | `GET http://106.53.102.240:6003/require/addDownloadTask` | 是 |
| 保存本地文件 | `GET data.mediumUrl` | 写入本地文件 |

下载和分析服务的正式字段定义见 [视频下载接口.md](./视频下载接口.md)，v4.0 搜索字段的实测结论见 [酷开影视搜索接口4.0实测协议.md](./酷开影视搜索接口4.0实测协议.md)。

## 3. 第一步：按片名检索专辑

### 请求

```http
GET https://movie-tc.skysrt.com/v2/search/v4.0?version_type=1&business_type=0&keyword={keyword}&category_en_name=VIDEO
```

| 参数 | 必填 | 固定/建议值 | 说明 |
|---|---:|---|---|
| `keyword` | 是 | 用户输入的片名 | 使用 UTF-8 URL 编码 |
| `version_type` | 是 | `1` | 本流程已验证的检索版本 |
| `business_type` | 是 | `0` | 影视业务线 |
| `category_en_name` | 建议 | `VIDEO` | 限定影视候选 |

### 选择结果

从 `data.video_info.category_type_list[].video_list[]` 中按标题、类型、来源、标签和海报选中专辑。后续“取分集”使用该对象的完整 `id`。

需要保存的字段：

| 字段 | 用途 |
|---|---|
| `id` | 分集接口的 `id` 参数，即完整媒资专辑 ID |
| `title` | 展示和本地文件命名 |
| `third_source` | 展示媒资来源；不是主片下载接口的必传参数 |
| `total_segment` / `update_segment` | 决定是否需要选择具体单集 |
| `images`、`category_name`、`tag_name` | 页面展示元数据 |

## 4. 第二步：从分集列表得到真实单集 ID

### 请求

```http
GET https://demo-media.skysrt.com/v2/getVideoSegmentList?node_type=res&id={searchResult.id}&page_size=60&ws=
```

| 参数 | 必填 | 值 | 说明 |
|---|---:|---|---|
| `node_type` | 是 | `res` | 点播影视资源 |
| `id` | 是 | 第一步选中结果的完整 `id` | 不要先移除来源前缀 |
| `page_size` | 是 | 覆盖所需集数的值，如 `60` | 本流程用 60 覆盖 48 集剧集 |
| `ws` | 否 | 空字符串 | 本次实测接口接受空值 |

### 响应字段与选集规则

响应路径为 `data.segments[]`。按 `segment_index` 选择目标集，集号从 1 开始。

| 字段 | 含义 | 能否用于下载接口的 `coocaaMId` |
|---|---|---:|
| `segment_index` | 集数序号 | 否，用于选择第几集 |
| `title` | 单集标题 | 否，用于展示和命名 |
| `id` | 分集对象的视频 ID | 否，不要假设它是 `coocaaMId` |
| `third_id` | 第三方视频 ID | 否，不能替代 `coocaaMId` |
| `coocaa_m_id` | 酷开单集 ID | **是** |

必须读取原始分集对象的 `coocaa_m_id`。页面常规字段映射如果未保留它，需要补充该字段；不能只依赖 `id` 或 `third_id`。

## 5. 第三步：查询下载状态并得到规范化 ID

### 请求

```http
GET http://106.53.102.240:6003/require/obtainMovieDetail?coocaaVId={albumId}&coocaaMId={segment.coocaa_m_id}&mediumType=1
```

| 参数 | 必填 | 值 | 说明 |
|---|---:|---|---|
| `coocaaVId` | 是 | 先使用搜索结果的完整专辑 `id` | 服务成功后会在响应中返回规范化值 |
| `coocaaMId` | 是 | `segments[].coocaa_m_id` | 第四步下载任务的单集键 |
| `mediumType` | 是 | `1` | 媒资自有内容 |

### 成功响应中的关键字段

```json
{
  "reason": "成功请求",
  "code": 0,
  "data": {
    "coocaaVId": "...",
    "coocaaMId": "...",
    "movieTitle": "...",
    "isDownload": 2,
    "analyzeStatus": 2,
    "mediumUrl": "https://...",
    "duration": 203,
    "resolution": "1920x1080"
  }
}
```

状态枚举：

| 字段 | `0` | `1` | `2` | `3` |
|---|---|---|---|---|
| `isDownload` | 未开始 | 下载中 | 已完成 | 下载失败 |
| `analyzeStatus` | 未分析 | 分析中 | 分析完成 | 分析失败 |

当 `code=0`、`isDownload=2` 且 `mediumUrl` 非空时，原片已准备好。应以该响应中的 `data.coocaaVId` 和 `data.coocaaMId` 作为后续流程的规范化 ID 保存下来。

## 6. 第四步：必要时发起下载

仅当查询结果未满足“已完成且有 `mediumUrl`”时调用此接口。

```http
GET http://106.53.102.240:6003/require/addDownloadTask?coocaaVId={canonicalVId}&coocaaMId={canonicalMId}&mediumType=1&priority=80
```

| 参数 | 必填 | 建议值 | 说明 |
|---|---:|---|---|
| `coocaaVId` | 是 | 第三步响应的 `data.coocaaVId` | 规范化专辑 ID |
| `coocaaMId` | 是 | 第三步响应的 `data.coocaaMId` | 规范化单集 ID |
| `mediumType` | 否 | `1` | 媒资自有内容 |
| `priority` | 否 | `80` | 交互式原片下载使用最高优先级档；接口默认 `50` 为低优先级 |
| `taskSource` | 否 | 按业务约定填写 | 任务来源 |

该接口会创建或加入服务端下载队列。返回 `code=0` 只表示请求受理，不表示本地文件已经可用。仅当 `isDownload=0`（尚未开始）时创建任务；`isDownload=1` 表示服务端正在下载，不能重复提交。随后每 2 秒重复第三步，直到 `isDownload=2` 且有 `mediumUrl`、服务端返回 `isDownload=3`，或用户取消。由于文件大小和上游响应差异很大，不能用固定客户端时长判定准备失败。

## 7. 第五步：保存原片到本地

每次准备下载本地文件前，重新调用“查询下载状态”获取最新 `mediumUrl`。该地址可能是带有效期参数的对象存储 URL，不应长期保存、写入日志或展示在页面中。

PowerShell 示例：

```powershell
$detail = Invoke-RestMethod -Uri $statusUrl
if ($detail.code -ne 0 -or $detail.data.isDownload -ne 2 -or [string]::IsNullOrWhiteSpace($detail.data.mediumUrl)) {
    throw '媒资尚未准备好'
}

$target = 'E:\coocaa\电影名 01_1080p.mp4'
Invoke-WebRequest -Uri $detail.data.mediumUrl -OutFile $target
```

保存策略：

1. 使用明确的目标目录，例如 `E:\coocaa`。
2. 如果同名文件已存在，先检查大小或哈希，不直接覆盖。
3. 下载完成后至少验证文件存在、大小大于 0；MP4 可额外检查文件头的第 4 至第 7 字节为 `ftyp`。
4. 记录规范化 VId/MId、集数、标题、时长、分辨率和本地路径，避免再次解析 ID。

## 8. 端到端实测：`麻将之王：四大流派篇` 第 1 集

以下数据用于回归验证，不应替代每次运行时的实时状态查询。

| 阶段 | 实测结果 |
|---|---|
| 搜索关键词 | `麻将之王` |
| 搜索专辑 `id` | `_oyk_ungoe0e04400` |
| 来源 | `youku` |
| 总集数 | `48` |
| 分集选择 | `segment_index=1`，标题 `麻将之王：四大流派篇 01` |
| 真正单集 ID | `coocaa_m_id=ungoe1i84400` |
| 规范化专辑 ID | `ungoe0e04400` |
| 下载状态 | `isDownload=2` |
| 分析状态 | `analyzeStatus=2` |
| 原片时长 | `203` 秒 |
| 分辨率 | `1920x1080` |
| 本地文件 | `E:\coocaa\麻将之王：四大流派篇 01_1080p.mp4` |
| 文件大小 | `19,439,910` 字节 |

分集接口中，第 1 至第 3 集的 `id` 都是 `ungoe0e04400`，但每一集的 `coocaa_m_id` 不同。因此，把 `segments[].id` 误当单集 ID 会导致下载服务返回 `movieRelationEntity is null`。

## 9. 可复用伪代码

```text
asset = searchV4(keyword).pickOne()
segments = getSegments(asset.id, node_type="res", page_size=60)
segment = segments.find(segment_index == selectedEpisode)
assert segment.coocaa_m_id is not empty

status = obtainMovieDetail(
  coocaaVId = asset.id,
  coocaaMId = segment.coocaa_m_id,
  mediumType = 1
)
assert status.code == 0

if status.data.isDownload == 0:
  addDownloadTask(
    coocaaVId = status.data.coocaaVId,
    coocaaMId = status.data.coocaaMId,
    mediumType = 1,
    priority = 80
  )

poll obtainMovieDetail until isDownload == 2 and mediumUrl is not empty,
  isDownload == 3, or user cancels

download latest mediumUrl to local target path
verify local MP4
```

## 10. 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| v4.0 有结果但无法下载 | 只拿到了专辑候选，未取得 `coocaa_m_id` | 先调用 GET 分集接口 |
| 下载服务返回 `movieRelationEntity is null` | 使用了 `segments[].id` 或 `third_id` 作为 `coocaaMId` | 改用 `segments[].coocaa_m_id` |
| `isDownload=0` | 服务端已受理，仍在调度队列，尚未开始下载 | 创建最高优先级任务后轮询状态 |
| `isDownload=1` | 服务端正在下载原片 | 继续轮询，不重复提交任务 |
| `isDownload=3` | 服务端下载失败 | 读取 `downloadFaliureReason`，按原因处理或重新发起 |
| 本地下载失败 | `mediumUrl` 已过期或网络不可达 | 重新查询状态获取新的 URL 后立即下载 |
| 页面播放器不能播 | 下载地址和浏览器播放地址不是同一能力，可能受 CORS、DRM 或 SDK 限制 | 本地文件下载和浏览器预览分别处理 |
