# Web 与 CLI 产品架构

Web 与 CLI 是两个独立产品。Web 是纯静态站点，数据保存在浏览器，适合部署和二次开发；CLI 是完整工作台和本地插件的主要产品，命令启动服务后在浏览器中使用自己的界面。Desktop 复用 CLI 界面与服务，只增加窗口与系统集成。

两端各自维护入口、路由、导航和构建产物，通过 `packages/workbench` 复用画布、业务页面、组件、状态和 adapter；不跨应用目录引用源码，不让 CLI 读取 Web 的 dist。`shared` 统一维护纯数据契约及 `canvas/` 中的画布文档与工具逻辑。

## 产品与数据归属

| 产品 | 入口与产物 | 业务数据位置 |
| --- | --- | --- |
| Web | `apps/web/src` → `apps/web/dist` | 当前浏览器的 localforage |
| CLI | `apps/cli/ui/src` → `apps/cli/ui/dist` → 发行包 `dist/ui` | 启动时指定的工作区 |
| Desktop | Electron 窗口复用 CLI 界面与本地服务 | 与 CLI 相同的目录格式 |

```text
apps/web                       apps/cli
  首页、路由、导航                ui/ 路由、导航、工作台
  浏览器入口                     本地入口 + 命令启动
        \                       /
          packages/workbench
      共用画布、页面、组件、业务 adapter
            |                 |
       浏览器实现            HTTP 实现
            |                 |
       localforage       packages/server
                              |
                          磁盘工作区
```

不增加通用功能注册框架，产品差异在各自路由和入口明确装配，共用页面不散布产品判断。网页发起生成并执行画布工具。纯 Web 由页面执行请求，CLI 与 Desktop 可按任务提交本地生成。

## 业务 adapter 与启动入口

`apps/web/src/main.tsx` 固定初始化 `workbench/startup/browser`；`apps/cli/ui/src/main.tsx` 固定初始化 `workbench/startup/local`。初始化完成后分别加载自己的路由和界面，导航由产品根部的 Context 提供。CLI 与 Desktop 共享本地入口和服务。

| 入口 | 业务存储 | 模型调用 | 渠道配置 | 外部资源请求 |
| --- | --- | --- | --- | --- |
| browser | BrowserStorage，浏览器 localforage | BrowserModels，浏览器执行脚本 | BrowserChannels，独立 localforage 存储 | BrowserNetwork，直连或用户开启的独立代理 |
| local | HttpStorage，同源服务写工作区磁盘 | HttpModels，本地服务执行脚本 | HttpChannels，服务保存密钥，网页只读取已配置状态 | LocalNetwork，同源服务自动发送请求 |

模型接口位于 `packages/workbench/src/services/api/models/types.ts`，覆盖图片、音频、普通文本、视频提交、视频查询和 Agent 模型请求；`runtime.ts` 保存入口注入的实现。`packages/model-runtime` 共用脚本运行器、内置脚本与媒体转换，宿主提供素材读取等能力。生成服务准备请求参数并保存结果，页面不自行选择执行环境。原视频轮询规则保留，查询使用提交时保存的模型标识和脚本源码。

初始化顺序为：本地模式先完成会话认证和项目读取检查；入口初始化存储与工作区配置实现并加载配置，再初始化网络、渠道和模型实现，最后加载共用界面。模型实现依赖的脚本库在导入时读取存储，不能提前静态导入。连接失败保留当前模式并提示重试。

渠道配置通过 `services/channels/` 的 ChannelAdapter 读取、保存和拉取模型。插件管理 adapter 随插件市场实现。素材持久化继续使用 StorageAdapter；裁剪、预览和节点渲染留在界面层。不为未来能力预建空接口，不增加只转发调用的包装层。

`services/workspace-config/` 的 WorkspaceConfigAdapter 读写 WebDAV 和对象存储配置，契约与默认配置位于 `shared/workspace-config`，页面使用独立的 `use-workspace-config-store`。浏览器实现使用 localforage，本地实现通过 `/api/workspace-config` 保存到私有集合；保存按顺序提交，后保存的内容生效。CLI 和 Desktop 将同一类设置的连续编辑按 1 秒合并，渠道单独保存，WebDAV 与对象存储合并保存。关闭设置或执行依赖新配置的操作会提前提交。启动读取失败不会改写默认配置，保存失败会阻止依赖配置的操作。浏览器偏好不重复保存工作区配置。

`services/storage-inspection/` 的 StorageInspectionAdapter 提供用量、分类列表、内容读取及已有预览。共享契约位于 `shared/storage-inspection`；浏览器实现只读 IndexedDB，本地实现通过 `/api/storage-inspection` 读取 FsStorage 的分类元数据，并复用存储与素材路径按需打开内容。页面不使用物理表名或文件路径。工作区文件大小与所在磁盘空间分别展示；私有配置、插件数据及剩余文件只计入分类用量。图片继续使用当前浏览器已有预览，统计和列举不下载原图，也不产生或清理业务数据。

`services/network/` 的 NetworkAdapter 负责 WebDAV、远程素材、提示词来源、插件下载与版本查询的请求地址。纯 Web 可配置独立代理；本地模式使用经过同源认证的 `/api/network`，忽略浏览器代理设置并隐藏对应设置页，不另开代理进程。同源资产、blob 和 data URL 保持原样。服务按需传递业务请求头，保留二进制传输和取消，不把外部 Cookie 写入本地会话。模型和渠道仍使用各自的专用接口。

`shared/model-execution` 保存单次调用配置和请求数据；`shared/model-http` 定义本地执行请求、素材引用、流式事件和固定错误码。两者不引用 AiConfig、DOM 或 AI SDK 工具函数。网页的 ModelAdapter 接口保留 AbortSignal、回调和 Blob，由具体实现转换。HTTP 请求只携带分组、模型、脚本快照及输入，不传渠道密钥或地址；服务核对已保存脚本，再读取渠道凭据。临时素材先保存，服务生成的素材先落盘再返回稳定引用。

内置聊天继续在网页运行 AI SDK 工具循环。文本脚本通过 `utils.runTextAgent(protocol)` 使用该能力；本地模式仅将模型请求交给服务，工具函数不跨进程传输。失败不静默切回浏览器执行。本地视频任务保存第三方编号、分组、模型、地址和脚本快照，由服务继续查询。每次查询使用当前工作区凭据。

## CLI 职责与生命周期

CLI 负责解析启动参数、打开数据目录、启动服务、输出访问地址，以及在显式要求时打开浏览器。业务读写由服务完成，画布操作仍通过网页完成。

安装版入口如下；源码开发直接运行 `pnpm dev --data-dir ~/Canvas --open`，不需要预先构建：

```bash
npx -y @basketikun/infinite-canvas@latest serve --data-dir ~/Canvas --open
```

| 参数或入口 | 行为 |
| --- | --- |
| `serve` | 启动静态托管、存储与网页连接服务，进程在前台运行 |
| `--data-dir` | 指定工作区目录，默认 `~/.infinite-canvas/workspace`，启动后输出实际绝对路径 |
| `--port` | 指定端口，默认沿用 `17371` |
| `--open` | 服务就绪后打开浏览器；不传时仅输出访问地址 |
| `--skip-plugins` | 本次跳过第三方插件并暂停相关任务，保留安装、启用意愿与业务数据；设置中可逐个重新启用 |
| `mcp` | 外部 Agent 的标准 MCP 接入入口，连接服务并定位网页，不运行 Agent 进程 |

发布包需要包含网页构建产物，用户启动时不需要克隆仓库、安装网页开发依赖或运行 Vite。开发和发布使用同一套业务模块，开发服务器不是发布版运行依赖。源码入口 `apps/cli/src/dev.ts` 将 Vite 作为页面托管实现注入 server，热更新连接复用同一个 HTTP 端口；发布入口 `src/index.ts` 注入 `dist/ui` 静态托管。server 只负责页面托管的接入和生命周期，不依赖 Vite。

一个服务进程绑定一个工作区目录。已被其他服务占用的目录应拒绝再次打开，避免两个进程各自持有不同版本。端口被占用或目录不可写时明确退出，不自动更换数据目录、清空内容或退回浏览器存储。固定监听回环地址，默认端口为 `17371`，可通过 `--port` 指定。目录使用系统文件锁，进程结束后自动释放；`.canvas.lock` 文件常驻，不代表目录仍被占用，不应手动删除。

正常停止时不再接收新写入，并等待已接受的写入结束后释放目录占用。浏览器尚未提交的修改不属于服务已接受的数据；网页必须区分“编辑中”“保存中”和“已保存”，不能把已更新内存当成保存成功。

## 模块和依赖边界

使用 pnpm workspace：`apps/` 放独立产品，`packages/` 放复用能力。产品自己选择路由、导航和启动 adapter，不互相依赖源码或构建产物。

```text
apps/
  web/src/               纯 Web 入口、首页、路由与导航
  cli/
    src/                 命令解析、服务启动与 MCP 接入
    ui/src/              本地工作台入口、路由与导航
  proxy/                 纯 Web 可选的独立请求转发程序
packages/
  workbench/src/         共用画布、业务页面、组件、store、客户端 adapter
  shared/src/            存储、模型、渠道、插件等公共数据契约
    canvas/              画布 schema、纯文档操作、工具定义
  model-runtime/src/     模型脚本执行、内置脚本与媒体处理
  server/src/            HTTP、WebSocket 推送、MCP、磁盘存储、模型执行与渠道管理
  plugin-sdk/src/        节点插件 SDK
plugins/                 工作台插件与最小插件模板（template）
agent-plugins/           外部 Agent 客户端插件，按插件名称独立存放
docs/                    文档站
```

`workbench` 是包含 React 和浏览器交互的业务包；`shared` 保持纯数据与纯逻辑边界。独立产品不等于复制所有业务代码，Web 可直接在自己的路由、导航与入口中缩减功能，CLI 可以增加自己的页面和本地能力。

```text
apps/web ──────────────► packages/workbench ─► shared / model-runtime
apps/cli/ui ───────────► packages/workbench
apps/cli/src ──────────► packages/server ────► shared / model-runtime
packages/plugin-sdk ──► shared
```

Desktop 复用 CLI 的本地工作台和 `server`，Electron 入口位于 `apps/desktop`。统一维护根目录 pnpm 锁文件，包之间显式声明工作区依赖。

### shared

`packages/shared` 是不依赖运行环境的公共契约与纯逻辑包。当前承载运行配置、通用存储接口与请求 schema、存储记录和错误、模型用途与调用脚本类型、单次模型调用数据与文本事件、插件元信息和安装记录，以及 `canvas/` 中的画布基础代码。Web、本地服务、CLI 与插件 SDK 按需从具体模块导入，不通过 store 或旧文件路径转发。

shared 允许使用 Zod 等纯数据处理库，不引用 React、DOM、Node、页面状态或具体存储实现。画布领域规则位于 `shared/src/canvas/`，节点组件和宿主回调留在工作台或插件 SDK，不将它们移入 shared。

shared 不决定执行位置。脚本运行器放在 `model-runtime`，浏览器和服务各自提供宿主实现。

### shared 的画布模块

`packages/shared/src/canvas/` 专注画布文档 schema、节点和连线规则、工具定义与纯文档操作，允许依赖 Zod 等纯数据处理库，不依赖 React、DOM、Node API 或其他业务应用包。共享文档契约不引用组件、store、临时 URL 或浏览器文件句柄；需要跨环境表达二进制时使用字节数据和媒体元信息。

该模块包含网页和本地服务共用的工具定义与纯逻辑，以及服务校验所需的文档 schema。不要把业务页面的类型、工具或节点渲染注册表整体搬入 shared。

文档操作与其他操作分开：

| 操作 | 所属层 |
| --- | --- |
| 节点和连线增删改、分组规则 | `packages/shared/src/canvas/ops/` 的纯文档操作 |
| 选中节点、移动视口、打开面板、页面导航 | 网页交互层 |
| 发起生成、查询任务、取消请求 | 网页通过 ModelAdapter 调用，本地服务执行已接受的生成任务 |
| 写磁盘、发 HTTP、推送变更 | server |

提取 `applyOps(doc, ops)` 时，应让操作携带已经确定的 ID 等数据，保持输入相同则结果相同。节点默认数据与 React 渲染注册需要分离，不能让 shared 为获取节点尺寸而加载组件。共享文档函数不能隐式触发生成。

纯文档操作已提取为确定性的 `applyOps`，网页 `CanvasSession` 统一调用并管理图历史、选区、视口与保存协调；UI、插件和既有 Agent 工具共用命令入口。文档提交与实际保存分别通知，生成任务提交和结果写回分开；网页继续持有实时编辑状态。服务不直接执行画布操作，未增加无头生成能力。

依赖约束应同时覆盖受限导入和 `window`、`document` 等全局对象；shared 的类型配置不加载 DOM 与 Node 全局类型。插件 SDK 中的 React 运行时继续留在 SDK，shared 不反向引用 SDK。

### workbench 与产品界面

共用组件、业务页面、hooks、store 和 adapter 放在 `packages/workbench/`；Web 与 CLI 各自拥有入口、路由和导航。文档数据结构在 shared 的 canvas 模块，编辑会话、选区、悬停、拖拽、面板和撤销历史仍在界面层。

保存的视口和界面偏好与共享文档内容区分管理，避免一个标签页缩放画布就覆盖另一个标签页的视角。调整字段归属时保留“重新打开项目恢复自己的视角”的交互，不把所有状态都塞进共享文档。

### server

server 负责同源静态资源、项目与素材读写、保存版本、变更通知、模型执行、渠道凭据和现有 MCP 网页连接。HTTP 请求处理、MCP 与 Desktop 调用同一套存储服务，不各自实现写文件流程。

它执行网页提交的生成任务，并在页面离开后继续保存结果。Agent 会话和画布工具仍由网页管理。

## 存储接口与模式选择

### 按业务定义存储能力

接口定义在 `packages/shared/src/storage.ts`，存储写请求 schema、版本记录、变更事件和错误定义在 `packages/shared/src/storage-data.ts`。用小型记录集合契约表达读取、写入、删除、遍历与可选变更订阅；项目按 ID 独立保存，媒体独立上传。Zustand 的选择、加载状态和函数不作为持久化内容。

| 适配器能力 | 实际内容 |
| --- | --- |
| projects | 每个 ID 一份带 schemaVersion 的画布文档；HTTP 实现按最后保存生效并保留删除记录 |
| images / media | 原始图片与音视频，网页侧用 Blob，服务侧以流写独立文件 |
| state | 素材库、调用脚本和插件清单的持久化切片，HTTP 映射为 library、scripts、plugins 三个逻辑集合 |
| imageRecords / videoRecords | 可更新、删除的生成记录 |
| chats | 以会话 ID 保存，内容包含所属项目 ID |
| pluginData(pluginId) | 插件可序列化私有数据 |
| preferences | 当前浏览器的视口与显示偏好，不发往服务 |

HTTP 使用 `/api/storage/:collection/:key` 读写逻辑记录，以 `{ value, clientId }` 提交；`/api/assets/:collection/:key` 独立上传或读取二进制，`/api/storage/events` 通过 WebSocket 推送变化通知。接口不暴露 IndexedDB 数据库名。媒体预览 URL 的创建与释放仍由网页媒体服务负责。

HttpAdapter 串行发送写入，服务按顺序提交，不校验读取版本或拦截覆盖。shared 的存储契约不使用 Blob、文件句柄或 Node 类型。

### 初始化与存储选择

Web 入口固定使用 browser 实现，CLI 界面入口固定使用 server 实现；各自独立构建，不再注入存储模式配置来切换同一份网页。

必须在项目加载、Zustand hydration 和聊天历史读取之前完成模式选择。当前模块加载时立即执行的数据读取，应改为在存储就绪后启动，避免先读浏览器数据再切换到磁盘数据。

server 无法连接时保留 server 模式，提示重试，不自动切到 BrowserAdapter。健康检查只判断服务是否可用，不决定用户的数据位置。运行中切换数据目录也不通过更换全局 adapter 实现。

存储实现由应用入口统一提供，业务模块直接从该入口使用。无需为此次改造把所有全局 store 改为 Context，或逐层向组件传递 storage。

### 数据归属

| 数据 | Web 模式 | CLI 与 Desktop 模式 |
| --- | --- | --- |
| 画布文档、我的素材、原始媒体、生成记录、聊天历史 | 浏览器 localforage | 工作区磁盘目录 |
| 调用脚本、插件安装信息与可持久化业务数据 | 浏览器 localforage | 工作区磁盘目录 |
| 缩略图、公共提示词缓存等可重建内容 | 浏览器缓存 | 在浏览器缓存，不作为唯一业务副本 |
| 选区、撤销历史、拖拽状态 | 页面内存 | 页面内存 |
| 主题、面板宽度、项目视口等设备偏好 | 当前浏览器 | 当前浏览器或 Desktop 窗口环境 |
| 渠道配置与 API Key | 浏览器独立 localforage 存储 | 工作区 `private/channels/`，网页读取时不返回密钥 |
| 生成任务 | 浏览器视频生成记录可保存第三方任务编号 | 画布和工作台保存本地 `taskId`，完整任务记录位于 `private/task/` |
| WebDAV 和对象存储配置、最近同步时间 | 浏览器独立 localforage 存储 | 工作区 `private/config/`；模型执行读取磁盘配置，不写入任务快照 |

同一工作区的渠道、WebDAV 和对象存储配置可在新浏览器连接后继续使用。主题、面板宽度和默认模型选择仍属于当前浏览器。认证网页会在内存中读取 WebDAV 和对象存储凭据用于编辑、同步和配置备份；这些配置不再写入浏览器偏好，完整配置备份仍包含相应凭据。

本地渠道密钥保存在权限受限的工作区文件中，尚未接入系统钥匙串；工作区整体备份包含这些密钥。通用存储 HTTP 路径不能读取私有集合。浏览器配置偏好不保存渠道；配置文件仅接受当前版本 7，导出的完整配置含按插件包分别保存的同步连接。

## 工作区磁盘格式

工作区可整体备份，当前实际布局如下：

```text
Canvas/
  workspace.json                 工作区 ID 与 schemaVersion
  .canvas.lock                   系统文件锁载体；进程结束自动释放占用
  projects/<project-id>.json      画布文档，删除后保留记录
  assets/
    images/<key-hash>.json        图片元信息及原始文件标识
    media/<key-hash>.json         音视频元信息及原始文件标识
    files/<file-id>               原始二进制文件
  library/<key-hash>.json         我的素材切片
  scripts/<key-hash>.json         调用脚本切片
  records/image/<key-hash>.json   生图记录
  records/video/<key-hash>.json   视频记录
  chats/<key-hash>.json           会话记录，含 projectId
  private/
    config/<key-hash>.json        WebDAV、对象存储与最近同步时间
    channels/<key-hash>.json      渠道、模型与密钥
    task/<key-hash>.json          以 taskId 为键的状态、结果与视频查询快照
  plugins/
    registry/<key-hash>.json      插件清单
    data/<plugin-hash>/<key-hash>.json
```

JSON 记录使用 `{ key, value }`；删除以 `value: null` 和 `deletedAt` 留下墓碑，供 WebDAV 同步删除记录。文件名中的 hash 仅对逻辑 key 编码，不表示媒体内容去重。项目 ID 限定为受控标识，其他 key 哈希后映射到固定目录，HTTP 不接受文件路径。

原始媒体在工作区内共享，项目、素材条目、生成记录和聊天附件保存稳定的素材标识。不做内容寻址去重；如果以后引入哈希，必须同时明确引用规则和清理行为，不能仅替换文件名。

持久化文档不保存 `blob:` 地址或重复的媒体 Base64。可访问的远程素材链接可以作为外部引用保留，但不能标记为已经落盘；只有成功写入的文件才拥有本地素材引用。

写入顺序为先保存素材，再提交引用它的文档；文档提交失败允许留下文件，不能提交指向未完成写入的本地引用。两种模式都不自动清理媒体，由用户在「设置 → 本地存储」主动清理未被任何记录引用的文件，浏览器与本地共用同一份引用扫描。

ZIP 导入导出与 WebDAV 同步复用这些文档和素材引用，通过所选存储接口读取和写入。导出仍由网页触发，不新增命令行导出功能。跨模式迁移使用明确的导入导出流程，不静默复制浏览器内容到服务目录。

文档带 `schemaVersion` 表示格式版本，不再保存用于覆盖拦截的修订字段。1.0 不兼容 0.x 的数据，不提前建立历史迁移框架；遇到没有对应升级路径的格式版本明确停止读取，不以空文档覆盖。

## 项目保存与多窗口使用

页面持有实时编辑状态，项目 store 负责持久化。保存状态包括待保存、保存中、已保存和失败，不提供覆盖拦截或冲突合并。

server 模式采用以下流程：

1. 进入项目时读取文档，素材按引用解析展示。
2. 编辑在本页内存中进行，按现有节奏自动保存当前项目，不上传全部项目列表，也不重复上传原始媒体。
3. 保存直接提交当前内容，服务串行写入，后保存的内容生效。新内容先写临时文件，再原子替换目标文件；工作区仍由一个本地服务持有。
4. 提交后通过 WebSocket 通知项目变化，通知不携带原始媒体或渠道凭据。本页自己的保存不触发重复加载。
5. 其他窗口的更新到来时，没有未保存编辑的项目静默加载新内容并重置撤销历史；正在编辑或保存的项目继续使用本页内容，不提示冲突或阻止后续保存。重连后重新读取项目列表与内容。

素材库、脚本、生成记录、聊天、配置与插件数据同样按最后保存生效；普通更新通知不弹窗要求重新加载。实际读取或保存失败继续显示固定错误提示，画布可重试保存、另存副本或放弃修改并重新加载。

BrowserAdapter 继续直接使用浏览器存储，不新增跨标签页同步或覆盖保护。

此次规划不新增自动保存间隔、请求超时、重试次数、素材大小或并发上限；实施时如确需调整这些行为，单独确定适用范围和失败处理。

## 生成与 MCP 的执行边界

两种模式共用生成流程和网页工具，模型请求由启动入口选择：

```text
内置聊天 ──► 网页工具执行 ──► 更新编辑状态 ──► 所选存储接口
外部 Agent ──► MCP 服务 ──► 目标网页工具 ──► 同一条保存路径
网页生成 ──► ModelAdapter ──► 浏览器或本地服务 ──► 模型服务
模型结果 ──► 所选存储接口 ──► 素材引用与文档
```

CLI 启动后即使没有打开网页，服务也能托管页面和管理持久化数据，但 MCP 画布工具仍需要目标网页。目标关闭或切换项目时，沿用明确的项目绑定与失败语义，不把请求改投其他项目，也不新增一套服务直接改磁盘画布的执行逻辑。

纯 Web 用户仍可使用当前 MCP 网页连接方式；本地数据模式把连接能力集成到同一个服务进程中。外部连接入口继续放在顶部设置的「Agent配置」，不为 CLI 增加第二个连接面板。

工作台与画布先保存本地 `taskId` 和结果位置，再向 `POST /api/models/task` 提交。服务先写工作区的 `task` 集合，再执行模型调用。相同标识和请求重复提交返回原任务，请求内容不同返回 409。页面通过 `GET /api/models/task/:taskId` 读取结果，工作台通过 `POST /api/models/task/changes` 一次等待多个任务的修订变化，按编号查进度时直接读取快照。流式文本保存最新累计内容，媒体保存为素材引用。页面重开后按原记录、项目、节点和批次位置显示结果。

服务退出时，已保存第三方编号的视频可在下次启动时续查。一次查询失败或达到原有查询次数上限时暂停，可通过 `POST /api/models/task/:taskId/resume` 再查原视频。其余尚未取得结果的生成标记为结果未确认，由用户决定是否重新生成。`POST /api/models/task/:taskId/cancel` 主动停止本地执行或查询。关闭网页仅结束页面等待，第三方是否继续执行取决于其服务。

MCP 文档写操作需要区分已应用到页面与已保存；server 模式对外报告保存成功时必须以持久化回执为准。生成工具仍只报告提交状态，完成情况通过任务查询获得。

未来确需无头编辑或生成时，再增加独立执行能力，并让它复用 shared 中的画布操作与同一个保存入口；不把未来需求加入本次 CLI 的验收范围。

## 本地服务访问边界

本地服务限定回环访问并校验 Host。存储、媒体、网页连接与工具请求只接受同源页面，不使用口令或会话 Cookie；纯 Web 页面不能连接本地服务。

文件访问只通过受控项目和素材标识映射到工作区，HTTP 请求不能指定任意磁盘路径。工作区用于保存用户数据，不承担对外托管任意目录的职责。

网页通过限定的业务请求使用本地能力。模型脚本在所选执行环境运行，本地脚本使用 Node.js 运行器，目前没有独立沙箱；安装和运行脚本应按本地代码处理。Agent 工具与节点渲染仍留在网页。服务详细诊断与对外提示分开，对外使用固定错误码和业务文案。

局域网共享、远程部署、多用户登录和系统钥匙串不属于当前实现。以后开放网络访问时，应重新设计认证和权限，不能仅修改监听地址。

## Desktop 启动与退出

Desktop 用 Electron 的 Node 模式运行 CLI。CLI 通过进程通信报告服务就绪后，窗口才访问已认证的本地工作台。窗口退出时先处理未保存提示，随后断开子进程连接，等待服务关闭并释放工作区。

它使用相同的文档格式、HTTP 契约和 CLI 本地工作台产物，不复制业务代码，也不绕过服务直接读写文件。CLI 与 Desktop 同时打开同一目录时，必须遵守工作区互斥规则，不能各自启动独立写入者。

桌面产物按当前操作系统和架构打包，项目不提供安装包；签名、安装和更新由自行分发者处理。
