# 场景搭建

将场景参考图转换为可编辑的画布生成流程，并最终在 Blender 中搭建场景。

## 前置条件

- 用户已提供参考图，或已将参考图作为画布图片节点上传。
- 画布已打开并连接 Canvas Agent；如果没有，先使用 `open-canvas`。
- Blender 已启动，Tripo Bridge 监听 `ws://127.0.0.1:60600`，用于接收画布模型。
- Blender MCP 已连接到 `127.0.0.1:9876`，用于执行场景布置脚本。
- 生成任务需要可用的图片和 3D 模型配置；不要假设 API Key 或代理一定可用。

## 工作流

### 1. 分析参考图并拆解对象

1. 确认参考图对应的画布图片节点；对话附件先用 `canvas_create_attachment_nodes` 创建真实图片节点。
2. 读取图片并自行分析，不要求用户手动整理 JSON。列出需要独立生成的对象，至少记录：对象名、类型（建筑/道具/植物/角色）、在画面中的相对位置、相对尺寸、朝向和是否需要多视图。
3. 用 `canvas_create_text_node` 将对象清单写入画布，方便用户检查和后续编辑。
4. 保留参考图节点作为所有单体图的视觉依据；不要把整张场景图直接当作每个对象的唯一建模参考。
5. 对象数量较多时，先处理主要建筑、道路/地面、关键道具和主要角色，再处理植物、装饰和次要物件。

推荐清单格式：

```text
对象名 | 类型 | 画面位置 | 相对尺寸 | 朝向 | 生成方式 | 备注
```

### 2. 生成单体参考图

每个对象使用 `canvas_generate_image` 生成独立参考图。提示词应包含对象特征、视角和材质，并尽量隔离背景：

```text
[对象名称]，[关键外形与材质]，与参考图保持设计一致，单体完整居中，正面或三分之四视角，纯白或透明背景，无其他物体，适合 3D 建模参考。
```

- 保持原型图中的风格、比例、颜色、朝向和关键结构。
- 建筑和道具优先生成能看清完整轮廓的单体图。
- 植物、路面和墙体等需要大面积重复的内容，可额外生成纹理或法线参考图，不要把纹理图当作模型参考图。
- 生成流程尽量分批执行，避免一次提交过多任务；等待当前批次状态明确后再继续。

### 3. 角色先做多视图，再生成模型

角色或人物不要默认只用一张图生成 3D：

1. 为角色生成正面、左侧、背面、右侧四个视角。
2. 保持四张图的服装、发型、比例和姿态一致，并为图片节点标记对应视角。
3. 四张视图准备完成后，将四个图片节点 ID 一起传给 `canvas_generate_model3d`。
4. 如果四视图中的部分任务失败，先补齐失败视角；不要用不一致的随机图片替代。
5. 静态场景人物保持参考图中的站立、行走或坐姿，不要为了建模擅自改成 T-pose。

### 4. 生成 3D 模型

对建筑、道具、植物和其他对象使用 `canvas_generate_model3d`，把对应单体图放入 `referenceNodeIds`：

- 单图生 3D：`referenceNodeIds: ["<image-node-id>"]`
- 多视图生 3D：`referenceNodeIds: ["<front-id>", "<left-id>", "<back-id>", "<right-id>"]`
- 通常启用纹理：`model3dTexture: "true"`
- 需要较高纹理质量时使用：`model3dTextureQuality: "detailed"`
- 只有用户明确需要时再启用 PBR、面数或四边面等额外参数。

使用 `generation_get_status` 查询任务；只有成功结果具备模型文件后，才进入导入步骤。失败对象记录下来并继续其他对象，不要声称模型已生成。

### 5. 导入 Blender

1. 先读取画布状态，收集成功的 3D 节点 ID。
2. 可用 `canvas_download_nodes` 触发浏览器下载作为备份；该工具只确认浏览器已触发下载，不提供可信的本地路径。
3. 使用 `canvas_import_to_blender` 批量导入模型：

```json
{
  "nodeIds": ["<model-node-id-1>", "<model-node-id-2>"]
}
```

4. 工具返回 `importing: true` 代表导入已经启动，不代表全部完成。等待网页提示或事件日志的最终成功/失败结果；不要因为看到启动结果就重复导入。
5. 如果导入失败，先区分 Blender Bridge 未启动、HTTPS 混合内容限制、模型文件缺失和格式不支持，再决定是否重试。

### 6. 在 Blender 中完成场景布置

导入完成后使用 Blender MCP 执行 Python。先检查当前场景和导入对象名称，再进行批量修改；不要默认清空用户已有的 Blender 场景，除非用户明确要求新建或重置场景。

布置顺序：

1. 建立或确认地面、道路、墙体等基础环境。
2. 按参考图的相对位置、朝向和层次放置主要建筑。
3. 放置道具、植物和人物，控制密度，避免所有对象集中在入口或画面中心。
4. 调整模型比例，优先保持原始比例，不要随意拉伸图片或模型。
5. 设置相机，先用宽构图确认整体布局，再调整局部机位。
6. 添加主光、补光和环境光；根据用户要求制作晴天、阴天或雨天版本时，分别保存设置或渲染结果。
7. 保存 `.blend`，并在输出中说明保存路径和仍需用户确认的视觉问题。

可按需使用以下 Python 结构，但必须根据当前场景实际对象名和用户目标修改：

```python
import bpy
from mathutils import Vector

# 先检查并按名称取得对象，不要无条件删除用户场景。
objects = {obj.name: obj for obj in bpy.context.scene.objects}

# 示例：为已导入对象设置位置、朝向和比例。
# objects["对象标题"].location = (x, y, z)
# objects["对象标题"].rotation_euler = (rx, ry, rz)
# objects["对象标题"].scale = (sx, sy, sz)

# 设置活动相机、灯光和输出路径前，先读取当前场景配置。
# bpy.context.scene.camera = objects["SCN_Camera"]
# bpy.context.scene.render.filepath = r"<用户指定的输出路径>"
# bpy.ops.wm.save_as_mainfile(filepath=r"<用户指定的 blend 路径>")
```

## 失败处理和边界

- 生成任务是异步的：用状态查询确认，不要用提交成功代替生成成功。
- 某个对象失败时保留失败清单，继续处理独立对象；只有用户要求完整一致时才暂停等待补生成。
- 3D 模型导入和 Blender 场景脚本是不同阶段；不要把 `60600` Bridge 当成 `9876` Blender MCP。
- Blender MCP 脚本执行前先读取场景，避免误删用户已有工作；删除、重置或覆盖 `.blend` 前必须确认。
- 不关闭用户已经打开的 Blender、浏览器窗口或标签页。
- 不继续渲染或生成超出用户明确范围的变体；耗时较长的批量生成、导入和渲染要先说明阶段性结果。
- 生成、导入、摆放和渲染都应如实报告已启动、已完成、失败或待确认状态。
